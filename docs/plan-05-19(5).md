## 二、逐项缺陷深度分析

### 2.1【硬性阻断 #1】策略性能未达最低门槛

**现状**：R9 Appendix C 记录的最终配置结果：

```
配置：MACD 10/26/8 + stop_loss 8% + profit_lock 12%/6% + time_stop 30d/3%
全周期（2018-06-11 ~ 2026-05-15）：
  Ann 24.87%，MDD 47.04%，Calmar 0.53，Sharpe 0.81
T4（2021-2022 熊市）：Ann -4.91%，Calmar -0.13
```

**根因**：
- R9 仅完成了"参数微调"（profit_lock 从 8%/4% 放宽到 12%/6%），**没有执行** S2 信号对比、S3 ATR trailing、S3-B regime gate 这三个可以真正改变性能曲线的实验
- 300750 在 2022 年下跌 73%，任何没有 regime 门控的趋势策略，在完整周期（含 T4）测试中 MDD 必然超过 40%
- `configs/single_stock/300750_best.yaml` 里明确写着 `enable_index_filter: false`，已知问题被留在配置里

**真实影响**：如果以当前配置上线，在下一个类似 T4 的熊市中，100 万本金可能亏损 47 万以上，且没有任何自动防御机制。

---

### 2.2【硬性阻断 #2】regime_gate.py 仅设计未实现

**现状**：`src/backtest/` 目录下**不存在** `regime_gate.py`。代码变更清单（第十节）把它标为"新建，P1"，执行计划把它放在 Day 3（0.5h），但实际未被编写。

`single_stock.py` 中存在 `enable_index_filter` 参数，使用了 `risk_off_multiplier_from_index`（极端行情下才触发，threshold 默认 5% 急跌），这不等同于 regime gate——前者是"指数崩盘时缩仓"，后者是"熊市不开新仓"，两者是完全不同的防御层级。

**真实影响**：即使明天把 `enable_index_filter: true` 打开，它调用的是 `risk_off_multiplier_from_index`（5 日急跌 ≥ 5% 才触发），这在 T4 的慢熊（2022 年缓慢下跌 73%）中**完全不起作用**。

```python
# src/backtest/regime_gate.py
class RegimeGate:
    """
    单股策略的市场 regime 门控。
    只控制新开仓许可，不强制平现有仓位。
    设计哲学：比 H-dual+dd 更宽松（防止 2019 年踏空），
              但比"永远允许"更保守（防止 2022 年频繁入场亏损）。
    """
    def __init__(self, ma_fast: int = 20, ma_slow: int = 60):
        self.ma_fast = ma_fast
        self.ma_slow = ma_slow

    def is_entry_allowed(
        self,
        date: pd.Timestamp,
        index_df: pd.DataFrame,  # CSI300 日线 OHLCV
    ) -> bool:
        """
        允许新开仓，当且仅当同时满足：
        1. CSI300 当日收盘 > MA(ma_fast)
        2. CSI300 MA(ma_fast) > MA(ma_slow)
        """
```

**要求**：
- 新增 `src/backtest/config.py` 中的 `regime_gate_enabled: bool`、`regime_ma_fast: int`、`regime_ma_slow: int` 参数

## 八、Phase S4：WFO 严格验证（生产前的最终关卡）

**前置条件**：S2 + S3 选出最优配置组合，regime gate 已集成。

### WFO 设计原则（来自 R8 教训）

- **折叠数 ≤ 4**：300750 只有 8 年数据，折叠太多导致每个 OOS 窗口太短
- **参数维度 ≤ 4**：超过 4 维的参数空间（> 300 个组合）时 IS/OOS 相关性崩溃
- **使用 S2/S3 结论缩减网格**：不重新搜索信号参数，只验证 S2/S3 选出的配置在不同时间段的稳定性

### WFO 参数网格（基于 S2/S3 结论填写）

```yaml
# configs/single_stock/300750_wfo_r10.yaml
# 待 S2/S3 完成后填入实际参数
wfo:
  n_folds: 3             # 3-fold，保证每折 OOS ≥ 1.5 年
  is_years: 3.5
  oos_years: 1.5
  min_trades_per_year: 1.5
  max_drawdown_limit: 0.40  # WFO 中放宽到 40%（OOS 通常比 IS 差）

  # 信号参数（来自 S2 选出的最优信号类型）
  # 在此填入 S2-A 结论：例如 macd_fast: [10, 12] 或 bar_period: [5, 8]

  # 出场参数（来自 S3 选出的最优机制，只微调）
  # 例如 atr_trailing_mult: [2.5, 3.0], intrapos_dd_limit: [0.04, 0.05]

  # Regime 参数固定（不在 WFO 中优化，避免过拟合）
  regime_gate_enabled: true
  regime_ma_fast: 20
  regime_ma_slow: 60
```

### S4 验收标准

|---|---|---|

## 十三、严禁重复尝试（继承自 R1–R9）

| 机制 | 结论来源 | 原因 |
|---|---|---|
| GBM 元标签（生产级） | SE5 | Sharpe 0.93→0.44，过拟合严重 |
| 周线门控（weekly_ma） | P1-B | 11/11 fold 被优化器拒绝 |
| rs_20/rs_60 动量因子 | E-3 | ICIR 强负 |
| H-dual+dd（MA60+MA120+DD15%）| R8 全轮 | 牛市踏空 100pp+，对 A 股 V 型反转过于保守 |
| 轮动框架（7 只股票）| R1–R8 | 6 只陪跑股无独立 alpha，复杂度税不可接受 |
| `portfolio_dd_limit`（硬性清仓）| H-4-A | T4 误伤 |
| 同时优化信号 + 止损 > 5 维 | R8/R9 教训 | IS/OOS 相关性崩溃 |
