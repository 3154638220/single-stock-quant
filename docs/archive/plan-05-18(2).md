**结论：当前 6 只已测标的无一达标。**

### 1.2 两轮实验揭示的系统性问题

#### 问题 A：000783 信号稀少是股票属性问题，不是参数问题

000783（券商股）的 MACD 信号天然稀少（年均约 1-2 次），因为：

- 券商股与大盘高度同步（Beta ≈ 1.5~2.0），真正的单边趋势只在大牛市中出现
- 放宽 `min_trades_per_year=1.0` 后，WFO 转而选出高频但高回撤配置（3.51% 年化，43.29% DD）
- **根本矛盾：在没有大盘牛市背景的情况下，000783 既没有足够的趋势性（无法高质量高频），也没有趋势延续性（高质量低频信号每次 MFE 利用率 76%，但 8-fold 只有 3 笔）**

**诊断结论**：单独对 000783 调参，不能解决其结构性信号稀少问题。需要**大盘状态联动**——只在 CSI300 进入趋势性上涨状态时才对 000783 开仓，这样虽然信号数不会增加，但信号质量会显著提升，hit rate 提升后年化才能达标。

#### 问题 B：300750 回撤来自入场决策，而非退出机制

sector_exit（20 日跌幅超 10%）未能压缩 2021-2022 回撤，因为：

- 300750 在 2021 年底以均线信号入场时，前期已涨幅超大（从 2020 年约 100 元涨至约 700 元）
- MACD 在 2022 年初仍然有"惯性红色"（价格滞后于基本面转变），信号错误入场
- 一旦入场，即使有 sector_exit，也需要板块跌 10% 才触发，此时股价已从高点回落 20%+

**诊断结论**：300750 的核心问题是**在历史高位附近入场**。需要入场前的价格位置过滤，而不是更好的退出机制。

#### 问题 C：大量已实现的入场过滤器从未在 WFO 中测试

代码中已实现但从未纳入 WFO 参数网格的入场过滤器：

| 参数 | 功能 | 在代码中 | 在 WFO 网格中 |
|---|---|---|---|
| `require_above_ma120` | 要求收盘价 > 120 日均线（半年趋势方向） | ✅ 已实现 | ❌ 从未测试 |
| `require_positive_rs60` | 要求 60 日相对强度 > 0（跑赢指数） | ✅ 已实现 | ❌ 从未测试 |
| `require_adx_min` | 要求 ADX > 阈值（趋势强度） | ✅ 已实现 | ❌ 从未测试 |
| `require_pullback_entry` | 等待信号后出现回调再入场 | ✅ 已实现 | ❌ 从未测试 |
| `atr_trailing_mult` | ATR 追踪止损（自适应波动率） | ✅ 已实现 | ❌ 从未测试 |
| `require_weekly_bullish` | 要求周线趋势为多头 | ✅ 已实现 | ❌ 从未测试 |

**这是最直接的机会**：在已有代码中系统测试这些过滤器，找到有效组合。

#### 问题 D：`compute_signal_quality` 评分几乎无效

代码审查揭示的评分缺陷：

- `run_len >= 2` 加 +15 分：BUY 信号触发在颜色切换首日（`dk_run_len=1` 是必然值），该规则**永远不会加分**，对所有信号都是 0 分
- `consensus_red_count == 3` 要求三个高度相关指标同时为红（MACD + 另外两个），独立性不足，实际是单因子
- P2-E 验证已证实：ATR 低于中位数的加分方向不稳，成交量规则效果因股而异，run_len 规则完全无区分度
- 结果：quality_score 在当前配置下近乎随机噪声，`min_quality_score` 过滤无效

#### 问题 E：WFO 目标函数的结构性双重惩罚

`_composite_score` 中存在对低频策略的双重惩罚：

1. `n_per_year < min_trades_per_year` → 返回 `-inf`（硬约束）
2. `trade_freq_score = min(n_per_year / 10.0, 1.0)` → 低频策略得分更低（软惩罚）
3. `reliability = min(1.0, n_trades/10.0)` → 低交易数对所有指标打折（第三重惩罚）

对于 000783 这样每年只有 1-2 笔高质量信号的股票，WFO 的三重频率惩罚系统性地选出"为了凑交易数而降低质量"的参数组合。

### 1.3 候选池的根本限制

`eligibility_25` 评分结果中，`exclude` 等级包含了 600519（茅台）、002594（比亚迪）、300760（迈瑞医疗）。这些是 A 股趋势性最强的龙头股。如果评分将它们排除，说明**评分标准本身存在问题**，而非这些股票不适合趋势策略。

### P0-A：入场过滤器系统测试（最高优先级，零新代码）

**背景**：代码中已有 6 个从未在 WFO 中测试的入场过滤器。这是成本最低、回报最确定的改进方向。

**实验设计**：单因子→组合渐进验证，每次只开启 1-2 个过滤器，与基准对照比较。

#### A.1 建立 P0 基准配置

新建 `configs/research/p0_baseline.yaml`：使用 wfo_stable 参数，**关闭所有过滤器**，仅保留最简单出场（profit_lock_trigger=0.12, profit_lock_trailing=0.05）。对 000783 和 300750 分别跑基准 WFO，记录 OOS Calmar 作为 A/B 对照基准。

#### A.2 MA120 过滤器测试

**假设**：要求收盘价 > 120 日均线（约 6 个月均线）可以过滤趋势末期和震荡期入场，显著提升胜率。

在参数网格中将 `require_above_ma120` 作为搜索维度：

```yaml
# 加入 wfo_000783.yaml 和 wfo_300750.yaml 的 param_grid
require_above_ma120: [true, false]
```

**预期**：`require_above_ma120=true` 在 300750 上应显著减少 2021-2022 年末期入场，从而降低回撤。对 000783，应过滤掉大盘下行期的弱信号。

**验收标准**：`require_above_ma120=true` 配置的 OOS Calmar 比基准提升 ≥ 0.10。

#### A.3 ADX 趋势强度过滤器测试

**假设**：在 DK 信号发出时，ADX > 20 意味着市场确实在趋势中（不是震荡），入场胜率更高。

```yaml
# 加入参数网格
require_adx_min: [0, 18, 22, 26]   # 0 = 关闭；非零 = 启用
adx_period: [14]                    # 固定，不搜索
```

**注意**：ADX 在 A 股证券股中的适用性需验证——证券股在大牛市中 ADX 可能滞后。

**验收标准**：`require_adx_min=22` 在两只标的上的 WFO Bootstrap Sharpe 正分比例 ≥ 60%。

#### A.4 RS60 相对强度过滤器测试

**假设**：60 日相对强度 > 0（跑赢 CSI300）的入场信号质量更高。这会过滤掉股票相对弱势时的错误入场。

```yaml
require_positive_rs60: [true, false]
```

**预期**：对 300750（2022 年相对弱势）效果显著；对 000783（大牛市中与指数高相关）可能效果有限。

#### A.5 ATR 追踪止损测试

**假设**：`atr_trailing_mult=2.0-3.0`（当前 ATR 的 2-3 倍距离设追踪止损）比固定 profit_lock 更自适应，在趋势延续时给更多空间，在反转时更快退出。

```yaml
# 替代当前的 profit_lock 机制（两者选其一测试）
atr_trailing_mult: [0, 1.5, 2.0, 2.5, 3.0]
atr_trailing_min_gain: [0.03, 0.05, 0.08]   # 盈利达到此值后才激活追踪
profit_lock_trigger: [0]                      # 关闭 profit_lock 对照
profit_lock_trailing: [0]
```

**验收标准**：ATR 追踪止损的 MFE 利用率（从 trade_forensics 输出）P50 ≥ 40%（当前 profit_lock 约 23-76%，目标是在保持较高值的同时增加交易数）。

### P1-A：000783 大盘状态联动入场

**背景**：000783 是 A 股典型的"市场 Beta 放大器"——只有在大盘牛市背景下，证券股才会产生有持续性的趋势。当大盘处于震荡或下跌时，MACD 信号往往是噪声。

**核心设计**：利用已有的 `index_ohlcv`（CSI300/510300 数据）实现指数状态门控入场。

#### A.1 指数趋势状态作为入场门控

当前代码已有 `enable_index_filter`（检测指数极端下跌）和 `enable_index_ma20_filter`（低于 MA20 时减半仓位）。需要新增一个更强的指数趋势状态门控：

**新参数**：`require_index_trend_bullish: bool = false`

入场逻辑（在现有入场过滤链中新增，约 15 行）：

```python
# P1-A: 指数趋势门控——CSI300 MACD 必须为正（histogram > 0）
if bool(require_index_trend_bullish) and index_ohlcv is not None:
    _idx_close = pd.to_numeric(index_ohlcv["close"], errors="coerce")
    _idx_macd_fast = _idx_close.ewm(span=12, adjust=False).mean()
    _idx_macd_slow = _idx_close.ewm(span=26, adjust=False).mean()
    _idx_macd_diff = _idx_macd_fast - _idx_macd_slow
    _idx_macd_signal = _idx_macd_diff.ewm(span=9, adjust=False).mean()
    _idx_macd_hist = _idx_macd_diff - _idx_macd_signal
    # 将指数 MACD 状态对齐到股票日期
    # 在信号日：指数 MACD histogram 必须 > 0
    _idx_hist_at_signal = _get_index_macd_hist(index_ohlcv, signal_date)
    if not (np.isfinite(_idx_hist_at_signal) and _idx_hist_at_signal > 0):
        continue  # 跳过此入场信号
```

**文件**：`src/backtest/single_stock.py`，入场过滤链（约 490-530 行区域），在 `require_positive_rs60` 检查之后新增约 20 行。新增辅助函数 `_get_index_macd_hist(index_ohlcv, date) -> float`。同时在 `_BT_PARAM_KEYS` 和 `_VALID_BT_KWARGS` 中注册 `require_index_trend_bullish`。

#### A.2 WFO 配置更新

在 `configs/wfo_000783.yaml` 的 `param_grid` 中新增：

```yaml
require_index_trend_bullish: [true, false]
require_above_ma120: [true, false]
```

**验收标准**：
- `require_index_trend_bullish=true` 配置的 OOS 8-fold 胜率（正收益 fold 比例）≥ 70%
- OOS 年化 ≥ 12%（达到晋级线的过渡目标）
- OOS 交易数合计 ≥ 6 笔（接受低频但高质量）

### P2-A：修复 signal_quality 评分函数

**目标**：使 `compute_signal_quality` 返回的 0-100 分对未来收益有真正的预测力，从而让 `min_quality_score` 过滤和 `quality_score_mode='scale'` 的仓位缩放真正有效。

#### A.1 移除无效规则

**文件**：`src/signals/generator.py`，`compute_signal_quality` 函数

必须修改：
- **删除 `run_len >= 2` 规则**（+15 分）：BUY 信号始终在颜色切换首日（run_len=1），该规则从未加分。替换为：若 `dk_run_len >= 3`（信号发出 1-2 天后 DK 趋势仍保持同向），加 +10 分（这需要用到信号前几日的趋势状态）。但更简单的做法是：直接将该规则改为 `close > close.shift(3)`（3 日价格动量为正），更有预测意义。

- **修复 ATR 规则**：`atr < atr_median` 方向错误（P2-E 已验证）。替换为：`atr_pct_rank > 0.3 and atr_pct_rank < 0.8`（ATR 既不过低也不过高，处于中等区间，代表趋势性波动而非滞涨或暴跌），加 +10 分。

- **降低共振规则权重**：`consensus_red_count == 3` 三个指标高度相关，从 +15 降至 +8，且改为 `>= 2` 以避免要求所有相关指标同时满足。

#### A.2 引入新的有效规则

基于 P2-E 验证结论，加入：

- **DK trend 运行质量**：`dk_value > dk_value.rolling(5).mean()` → 当前 dk_value（MACD histogram 相对强度）高于 5 日均值，代表动量加速，+12 分
- **价格距 52 周低点的位置**：`(close - close.rolling(252).min()) / close.rolling(252).min() > 0.20` → 不是从底部刚反弹的弱势信号，+10 分（避免在极度超卖反弹中入场）

#### A.3 验证评分有效性

修改后，运行验证脚本确认质量分对前向收益的预测力：

```bash
python scripts/validate_signal_quality_rules.py \
  --symbols 000783 300750 000333 600519 \
  --start 2018-01-01 --end 2026-05-01 \
  --output data/output/signal_quality_validation/v2/
```

**验收标准**：修改后的质量分与 20 日前向收益的 Spearman 相关系数 ρ ≥ 0.10（从当前几乎 0 提升到有意义的正相关）。

### P2-B：重新评估高趋势性标的

**背景**：当前 eligibility_25 评分将 600519（茅台，2017-2021 年 A 股最强趋势股）列为 exclude，说明评分体系有系统性缺陷——可能惩罚了趋势性过强的股票（趋势太强导致 MACD 信号频率低，触发频率评分惩罚）。

#### B.1 重新检视 eligibility 评分逻辑

审查 `scripts/score_symbol_eligibility.py` 中的评分维度，特别是：

- **信号频率评分**：如果对"年均有效 BUY 信号 < 3 次"惩罚，则 600519 这种慢牛股会被错误排除（慢牛股每年只需 1 次好信号就够）
- **滚动 Sharpe 评分**：600519 的 Sharpe 主要集中在 2017-2021 年，其余年份较低，滚动中位 Sharpe 可能被拉低

修改评分逻辑：将信号频率评分的下限从"年均≥3次"改为"年均≥1次"，避免对高质量低频标的的错误排除。

#### B.2 对高趋势性标的运行 WFO

根据修正后的评分，对以下标的运行完整 WFO（使用 `wfo_stable.yaml` + `require_above_ma120=true` + `require_positive_rs60=true`）：

### P3-A：WFO 目标函数去双重惩罚（仅针对低频标的）

**目标**：消除 `_composite_score` 对 000783 类低频策略的三重软惩罚，让评分真实反映质量而非偏向高频。

**文件**：`src/backtest/wfo.py`，`_composite_score` 函数

当前问题：
```python
trade_freq_score = min(float(n_per_year) / 10.0, 1.0)        # 惩罚 1
reliability = min(1.0, max(float(res.n_trades), 0.0) / 10.0) # 惩罚 2
reliability = max(reliability, 0.30)                          # 保底但仍惩罚低频
# + min_trades_per_year 硬约束                                 # 惩罚 3（合理，保留）
```

**修改方案**（通过 WFO config 参数控制，不改变通用行为）：

在 `wfo_config` 中新增可选参数 `reliability_mode: str = "standard"`：

- `standard`（默认）：当前行为，对 ≥10 笔交易给满分可靠度
- `quality_first`：仅用于低频标的（如 000783），`reliability = 1.0`（只要通过硬约束就不额外打折），`w_trade_freq = 0`（不奖励高频）

```yaml
# 在 wfo_000783.yaml 的 wfo 节点下新增
reliability_mode: quality_first   # 关闭三重惩罚，只保留 min_trades_per_year 硬约束
```

**验收标准**：在 000783 WFO 中，`quality_first` 模式下，breakout 类配置（高 Calmar 但低频）能被选出，而不被 reliability 折扣淘汰。

profit_lock_partial_exit_pct: float = 0.0    # 0=全退（当前），0.5=退出50%

状态机修改（`single_stock.py`，约 40 行新代码）：

**验收标准**（才决定推进）：在 000783 全样本测试中，`partial_exit_pct=0.5` 相比全退的总收益提升 ≥ 10%，最大回撤无增大。
