## 0. 核心判断：问题在哪里

经过 25 阶段、16 轮以上实验，**根本瓶颈已经清晰**：

| 层次 | 现象 | 根因 |
|---|---|---|
| 信号层 | DK BUY 信号单调性差，bucket return corr 从未转正 | DK 指标本质是 MACD 柱体正负转换——滞后指标，在震荡市产生大量假信号 |
| 出场层 | MDD 平均 47%，出场时已回吐大量利润 | DK SELL 依赖 MACD 柱体再次转负，比价格高点滞后约 2 个 EMA 周期 |
| Meta-label 层 | p_win 排序能力弱，提高权重反而恶化结果（E16） | 每 fold 训练样本仅 5–15 个，16 个特征 + 逻辑回归 = 严重欠拟合/噪声过拟合 |
| WFO 层 | IS/OOS 相关性仍为负，参数选择不稳定 | 504 天训练期内 BUY 信号仅 15–25 次，样本不足以区分参数质量 |
| 标的层 | 000002、600048 等标的持续负期望 | DK 策略在非趋势性标的（地产/周期）上结构性失效 |

**组合层已接近极限**：E21（滚动灰名单 + 静态排除）是当前最优（Sharpe 0.278），继续叠加组合层机制的 ROI 极低。

**本计划专注单股层**，目标是把**单股 WFO OOS 中位 Sharpe 从 ~0.15 提升到 ≥ 0.40**，这是组合层能发挥作用的前提。

## 1. 五大核心缺陷详解

### 1.1 DK 指标：被误解的趋势信号

**代码事实**（`src/indicators/dktrend.py`）：

```python
# MACD_CROSS 模式（默认）
fast = ema(close, macd_fast)   # EMA(12)
slow = ema(close, macd_slow)   # EMA(26)
diff = fast - slow
dea  = ema(diff, macd_signal)  # EMA(9) of DIFF
dk_value = diff - dea          # = MACD 柱体（histogram）

# dk_color = "red"  ← 仅代表 MACD 柱体 > 0，不代表趋势强
# dk_signal = "buy" ← 仅代表柱体从负转正，是极普通的 MACD 金叉
```

**后果**：
- MACD 柱体在震荡市中可以每月翻转 1–2 次，导致频繁假信号
- `dk_color = "red"` 期间价格可能横盘甚至小幅下跌
- DK 对真正强趋势（单边上涨）确实有效，但对震荡标的完全失效
- `dk_run_len` 度量的是"柱体持续正值的天数"，与趋势质量不等价

### 1.2 出场机制：利润回吐黑洞

**代码事实**（`src/backtest/single_stock.py`，默认配置）：

```python
elif sig == "sell" and planned_long:
    j = _next_sell_index(df, i + 1, code)
    actions.setdefault(j, "sell")  # 只在 dk_signal == "sell" 时出场
```

从 BUY 到 SELL 的时间链：
1. 价格见顶（t=0）
2. EMA(12) 开始下弯（t ≈ +5 天）
3. DIFF = EMA(12) - EMA(26) 开始下降（t ≈ +8 天）
4. DEA = EMA(9) of DIFF 开始下降（t ≈ +12 天）
5. DIFF < DEA，柱体转负 → dk_color 变绿 → dk_signal = "sell"（**t ≈ +15–25 天**）
6. 次日开盘卖出（T+1 执行）

**结论**：最快情况下，价格高点后 15 天才能出场；最坏情况（慢速反转）可能在高点后 30–40 天才出场，期间损失 15–30%。这就是 MDD 47% 的直接原因。

### 1.3 Meta-label：样本饥渴的伪学习

**数量问题**：

| 配置 | 估算 |
|---|---|
| 单股 6 年 BUY 信号总数 | 50–80 次 |
| WFO 训练期（504 天 = 2 年） | 约 15–25 次信号 |
| 每 fold 测试信号 | 约 5–10 次 |
| 特征数量 | 16 个 |
| 有效自由度 | 约 1–2（样本数/特征数 ≈ 1） |

**标签问题**：`profit_aware` 标签 = 20 日后收益 > 0 且持仓期 MDD < 8%。这个定义意味着：任何市场震荡 > 8% 的 BUY 信号都被标记为 0，而 A 股标的日内振幅本就较大，导致正样本极少（估计正样本率约 25–35%），类别严重不平衡。

**特征问题**：全部 16 个特征都是技术指标（MA、ATR、Volume、MACD 方向），高度共线，且与产生 BUY 信号的 DK 指标本身存在循环关系（特征 ← DK 同源），信息增量极低。

**模型问题**：`LogisticMetaModel` 是纯手写逻辑回归，无正则化搜索，无类别权重，无特征选择。在 15 个样本 + 16 个特征上，任何线性模型的输出都主要是噪声。

### 1.4 WFO 参数优化：在沙上建楼

默认参数网格：`macd_fast[4] × macd_slow[3] × macd_signal[3] × min_run_len[3] × stop_loss[3] = 324 组合`

每个 IS fold（504 天）内约有 15–25 次 BUY 信号，对应 15–25 次交易，Sharpe 估计的标准误差约 ±0.3–0.5。在这个精度下，324 组合的最优参数选择**等于在噪声中随机挑选**。

更糟的是：`_composite_score` 同时使用 Sharpe（0.45）、Calmar（0.25）、年化收益（0.15）、MDD（-0.10）——这些指标在 15 次交易样本下全部不可靠。

### 1.5 标的筛选：DK 策略有结构性适用边界

DK（MACD）策略在**趋势标的**（新能源龙头、消费白马）上表现好，在**低波动率 + 非趋势标的**（地产、银行）上结构性失效。

E19 归因已证明：000002（万科）、600048（保利）在所有 regime 和 horizon 下均负期望。这不是参数问题，而是策略与标的的结构性不匹配。但当前没有一套系统化的"标的适用性评分"机制，watchlist 依靠人工判断。

## 阶段 S1：交易级诊断（Trade-level Forensics）

**目标**：量化现有策略的"利润回吐率"，找到出场失效的具体数字。

### S1.1 MAE/MFE 全量统计

**新增文件**：`scripts/analyze_trade_forensics.py`

对所有 WFO OOS 交易计算：

| 指标 | 定义 | 目的 |
|---|---|---|
| MFE（最大有利移动） | 持仓期内收盘价相对入场价的最高涨幅 | 策略理论最大盈利潜力 |
| MAE（最大不利移动） | 持仓期内相对入场价的最大回撤 | 止损设置依据 |
| Exit Efficiency | 实际出场收益 / MFE | 出场质量（<0.5 说明回吐了一半以上利润） |
| Time to MFE | BUY 信号到达 MFE 的天数 | 最佳持仓窗口 |
| MFE/MAE Ratio | 盈亏比 | 信号质量指标 |

**预期发现**：Exit Efficiency 估计在 0.2–0.4 之间，说明出场时已回吐 60–80% 的峰值利润。这是优化出场的量化基础。

**输出文件**：`data/output/experiments/S01_forensics/trade_mfe_mae.csv`

```bash
python scripts/analyze_trade_forensics.py \
  --watchlist configs/watchlist_25.txt \
  --start 2020-01-01 --end 2026-05-08 \
  --export data/output/experiments/S01_forensics/
```

### S1.2 持仓期 DK 值动态分析

对每笔交易，记录持仓期内 `dk_value` 的峰值日期和出场日期，计算"dk_value 峰值到出场"的时间滞后（天数）分布。

**预期发现**：dk_value 峰值出现后，平均再持有 12–20 天才出场，这 12–20 天是主要的利润回吐窗口。

## 阶段 S2：出场机制重构（Exit Engine Redesign）

**目标**：在不降低入场质量的前提下，把 Exit Efficiency 从 ~0.3 提升到 ≥ 0.5，MDD 目标 ≤ 35%。

### S2.1 DK 柱体动量衰减早退出

**核心假设**：dk_value 开始连续下降时（柱体缩量），即使仍为正，也是趋势衰竭的早期信号。

**改动文件**：`src/backtest/single_stock.py`

```python
# 新增出场条件：dk_value 连续 N 日下降（momentum fade）
if params.dk_fade_exit_n > 0 and in_pos:
    window = dk_values[max(0, i - params.dk_fade_exit_n + 1): i + 1]
    if len(window) >= params.dk_fade_exit_n:
        if all(window[j] > window[j+1] for j in range(len(window)-1)):
            # 连续下降 N 天，触发动量衰减出场
            actions.setdefault(i + 1, "dk_fade_exit")
```

新增 `DKTrendParams` 字段：
- `dk_fade_exit_n: int = 0`（0 = 禁用，推荐测试 3–5）

### S2.2 持仓最大回撤止损（Intra-position Drawdown）

**核心假设**：入场后从持仓最高点回撤超过 N% 时，无论 DK 状态如何，立即止损。这比固定止损更智能（跟随趋势走），比移动止损更激进（基于最高收盘而非最高价）。

**改动文件**：`src/backtest/single_stock.py`

```python
# 持仓中追踪最高收盘价（已有 highest_close）
if in_pos and intrapos_dd_limit > 0:
    cur_close = float(df.loc[i, "close"])
    dd_from_peak = (highest_close - cur_close) / highest_close
    if dd_from_peak > intrapos_dd_limit:
        actions.setdefault(i + 1, "intrapos_dd_stop")
```

新增参数：`intrapos_dd_limit: float = 0.0`（推荐测试 0.12–0.18）

### S2.3 持仓时间 + 利润联动退出

**核心假设**：持仓超过 N 天后，如果浮盈低于 M%，说明信号质量差，不应继续持有。

改进现有 `time_stop_days` / `time_stop_min_return`，让时间止损与绝对收益门槛联动：

```yaml
time_stop_days: 30        # 超过30天
time_stop_min_return: 0.03 # 若收益 < 3% 则退出
profit_lock_trigger: 0.08  # 浮盈超过8%后启动利润保护
profit_lock_trailing: 0.04 # 利润保护：最高点回撤4%出场
```

### S2.4 实验矩阵

| 实验 ID | 出场配置 | 核心假设 | 验收目标 |
|---|---|---|---|
| SE2a | DK fade exit N=3 | 柱体3日连降即退 | MDD ≤ 38%，胜率不下降 |
| SE2b | DK fade exit N=5 | 柱体5日连降才退（减少误触发） | Exit Efficiency ≥ 0.45 |

## 阶段 S4：Meta-label 系统重建（v3）

**目标**：让 meta-label 的 p_win 真正有排序能力（bucket return corr 在5/20日维度转正）。

### S4.1 样本扩充：从信号级到日级

**根本问题**：当前只在 BUY 信号日提取特征（50–60 次/6年），样本太少。

**解决方案**：在 DK 红色状态的**所有交易日**提取特征，标签改为"该日起 N 日的持仓收益是否超过阈值"。这样每个标的可以有 500–800 个训练样本（红色天数）。

注意避免 look-ahead：特征和标签都严格 T 日以前数据。

```python
# 新标签逻辑
def build_daily_labels(
    ohlcv: pd.DataFrame,
    dk_trend: pd.DataFrame,
    *,
    forward_days: int = 10,
    return_threshold: float = 0.03,  # 10日涨幅 > 3% 为正
) -> pd.DataFrame:
    """对 dk_color == 'red' 的每一天构造特征和标签。"""
```

**好处**：训练样本从 50 增加到 500+，模型有实质性学习能力。

### S4.2 标签目标重设计

当前 `profit_aware` 标签：20 日后收益 > 0 AND max_dd < 8%

**问题**：`max_dd < 8%` 过于严苛（A 股日内振幅 1.5–2%），导致正样本率 < 30%，模型倾向于预测全 0。

**新标签选项**（逐步测试）：

| 标签 ID | 定义 | 正样本率估计 | 适用性 |
|---|---|---|---|
| `label_v1` | 10日后收益 > 0 | ~50% | 基础，信息量低 |
| `label_v2` | 10日后收益 > ATR(14) | ~40% | 要求超过正常波动 |
| `label_v3` | MFE/MAE > 2.0（盈亏比） | ~40–45% | 直接优化盈亏比 |
| `label_v4`（推荐）| 10日后收益 > 0 AND 5日内最大回撤 < 2×ATR | ~42% | 平衡利润与风险 |

推荐从 `label_v4` 开始，ATR 自适应的止损门槛更符合 A 股特性。

### S4.3 模型升级：GBM 替代逻辑回归

**新增文件**：`src/models/meta_label_gbm.py`

```python
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline

class GBMMetaModel:
    """Gradient Boosting meta-label classifier.
    
    相比 LogisticMetaModel 的优势：
    - 处理特征间非线性关系
    - 内置特征选择（feature importance）
    - 对样本不足更鲁棒（树深度控制过拟合）
    """
    
    def __init__(
        self,
        n_estimators: int = 100,
        max_depth: int = 2,       # 浅树，防止过拟合
        learning_rate: float = 0.05,
        subsample: float = 0.8,
        min_samples_leaf: int = 5, # 叶节点最少5个样本
        class_weight: str = "balanced",
    ):
```

**关键超参**（解决小样本过拟合）：
- `max_depth = 2`：禁止深度特征交互
- `min_samples_leaf = 5`：叶节点至少 5 个样本
- `n_estimators = 50–100`：不需要太多树
- `subsample = 0.8`：Stochastic GBM，提升泛化

### S4.5 WFO 训练方案调整

**目标**：建立一套自动化的"DK 策略适用性评分"，替代当前的人工 watchlist 维护。

| 维度 | 指标 | 权重 |
|---|---|---|
| 趋势质量 | DK 红色期间价格方向一致性（红色天数中价格上涨占比） | 30% |
| WFO OOS 历史表现 | 最近 2 年 WFO OOS Sharpe（至少 3 个 fold） | 40% |
| 信号频率 | 年化 BUY 信号次数（目标 4–12 次/年，太少或太多都不好） | 15% |

### S6.2 稳定性优先的评分函数

**新评分函数**（替换现有 `_composite_score`）：

```python
def _new_composite_score(res, *, train_days: int) -> float:
    """稳定性优先的复合评分。
    
    增加对 n_trades 的绝对要求，避免在极少交易上产生虚高 Sharpe。
    """
    years = train_days / 252.0
    n_per_year = res.n_trades / years
    
    # 硬约束（更严格）
    if n_per_year < 4:        # 年化少于4笔，信号太稀疏
        return -np.inf
    if n_per_year > 24:       # 年化多于24笔，可能过拟合震荡
        return -np.inf
    if res.max_drawdown > 0.40:
        return -np.inf
    
    # 软评分：重视 Calmar（控回撤），降低纯 Sharpe 权重
    sharpe = np.clip(res.sharpe_ratio, -2, 3)
    calmar = np.clip(res.calmar_ratio, -1, 2)
    
    return 0.35 * sharpe + 0.40 * calmar + 0.25 * (1 - res.max_drawdown)
```

### S6.3 OOS 评估使用 Bootstrap CI

对 OOS 的 Sharpe，不只看点估计，还计算 Bootstrap CI（1000 次重采样）：

```python

    """返回 Sharpe 的 95% Bootstrap 置信区间下界和上界。"""
```

只有当 Bootstrap CI 下界 > 0.0 时，才认为 OOS 表现"显著正收益"。

## 7. 风险与注意事项

1. **过滤掉的信号不可恢复**：SE3 的入场条件强化会减少信号频率 20–40%，需验证剩余信号的质量确实更高（胜率提升），而不只是数量减少。用每个月的 OOS 期内信号质量做稳定性检验。

2. **出场机制的参数需要 WFO 验证**：`dk_fade_exit_n`、`intrapos_dd_limit` 是新参数，必须纳入 WFO 网格，不能靠全样本 IS 回测选定。

3. **GBM 的日级样本存在自相关**：同一标的连续红色天数的特征高度相关，需要 WFO 训练/测试严格时间切分（不能随机切分），否则会严重高估模型性能。

4. **ADX 参数敏感性**：`adx_period = 14` 是标准值，但 A 股不同板块的趋势周期不同。建议先做参数敏感性分析，确认 ADX ≥ 20/22/25 在 watchlist 上的过滤率分布。

5. **行业 RS 特征依赖行业映射**：`industry_rs_20` 特征需要 `configs/industry_map.csv`，已在 E22 中引入，确认所有 watchlist 标的都有行业映射。

6. **成功标准仍是 OOS**：SE2/SE3 的任何改动只有 WFO OOS 指标改善时才算通过，全样本 IS 提升不计。
