`s_final.yaml` 注释揭示了 SE2–SE3 实验的关键结论：

| 结论 | 细节 |
|---|---|
| **SE2d 胜出** | 利润保护（trigger 8% / trailing 4%）是单一最有效的出场改进 |

当前已完成代码、尚未验证的关键实验：

| 缺口 | 严重程度 | 描述 |

| ❌ s_final_wfo.yaml 的 WFO OOS 从未运行 | **最高** | 不知道利润保护机制是否在 OOS 中成立 |
| ❌ SE4 GBM + label_v4 + 日级样本从未跑 WFO | **高** | GBM 代码就绪但无实验数据 |
| ❌ IS/OOS 相关性在新配置下未测 | **高** | 历史负相关未被证伪 |

**结论：当前模型效果存疑。IS 改善令人鼓舞，但在验证 WFO OOS 之前，不能宣称目标已达成。**

## 二、行动计划

### 优先级排序原则

1. **诊断先于优化**：在加更多机制前，先弄清楚现有机制在 OOS 中的表现
2. **OOS 是唯一标准**：任何 IS 结论必须在 WFO OOS 中复现才算有效
3. **最少有效变更**：一次只验证一个假设，避免叠加效果混淆

**目标**：确认 Exit Efficiency 基线数字，为后续改进提供锚定。  
**优先级**：高（快，无需 WFO，约 10 分钟）

```bash
python scripts/analyze_trade_forensics.py \

  --export data/output/experiments/S01_forensics/
```

**验收标准**：
- 生成 `trade_mfe_mae.csv`，包含每笔交易的 MFE、MAE、Exit Efficiency
- 确认 Exit Efficiency 中位数（预期 0.20–0.40）
- 确认 Time to MFE 分布（预期峰值在 10–25 天）

**如果 Exit Efficiency < 0.30**：说明出场仍是主要瓶颈，优先做行动 2  
**如果 Exit Efficiency 0.30–0.50**：出场已有改善，重点转向行动 3（WFO OOS 验证）

### 行动 5：WFO 参数网格审查（如行动 2 结果不理想时执行）

**触发条件**：行动 2 中 OOS Sharpe < 0.10 或 IS/OOS 相关仍为负

**问题诊断**：当前 `s_final_wfo.yaml` 把 `profit_lock_trigger` 和 `profit_lock_trailing` 放入 WFO 网格（各 3 个值），但这两个参数正是 IS 实验中选出的"最优"参数——如果 WFO 在 IS 中选这些参数，OOS 可能无法泛化。

**解决方案 A：固定利润保护参数，只优化 MACD 参数**

```yaml
# wfo_stable.yaml — 只优化信号参数，出场参数固定
backtest:
  stop_loss_pct: 0.08
  time_stop_days: 30
  time_stop_min_return: 0.03
  profit_lock_trigger: 0.08   # 固定，不进入网格
  profit_lock_trailing: 0.04  # 固定，不进入网格

wfo:
  param_grid:
    macd_fast: [10, 12, 14]
    macd_signal: [8, 9, 10]
  # 仅 9 个组合，大幅减少过拟合
```

**解决方案 B：稳定性优先选参（已实现，但未启用）**

```bash
python scripts/run_wfo.py \
  --symbol 300750 \
  --config configs/wfo_stable.yaml \
  --stability-weighting \  # 使用 _select_stable_params() 而非峰值选参
  --start 2020-01-01 --end 2026-05-08 \
  --output data/output/experiments/WFO_stable_300750/
```

**解决方案 C：参数锁定（极简策略）**

如果 WFO OOS 无论如何都无法超过固定参数，直接放弃 WFO 参数优化，使用固定的 `s_final.yaml` 参数在所有标的上运行，通过 symbol eligibility 筛选控制质量。

## 四、已知风险与注意事项

### 风险 1：利润保护参数过拟合

`profit_lock_trigger=0.08 / profit_lock_trailing=0.04` 是在 IS 全样本实验中找到的最优值。WFO 中把这两个参数放入网格意味着每个 fold 的 IS 又重新优化，可能导致 OOS 中结果不稳定。  
**缓解**：行动 5 中用固定出场参数、只优化 MACD 参数的方案来测试。

### 风险 2：GBM 日级样本自相关

同一标的连续红色天数的特征高度时间自相关（`dk_value` 变化缓慢），WFO 时间切分能隔离 IS/OOS，但 IS 内部的训练集如果不考虑自相关，模型评估的交叉验证会高估泛化能力。  
**缓解**：`wfo.py` 已用时间切分（非随机），但 `build_daily_labels` 训练过程中如使用了任何 `cross_val_score`，需确认使用 `TimeSeriesSplit`。

### 风险 3：SE3 入场过滤降级的诊断

SE3 全部降级（IS 结果变差）可能有两种原因：  
(a) 入场过滤本身无价值  
(b) IS 样本不足以检测其效果（信号减少 30% 后 IS Sharpe 的标准误差更大）  
**建议**：在 OOS 数据上用 permutation test 检验 SE3a（突破过滤）是否确实无增量——避免 IS 噪声误导了结论。

### 风险 4：WFO 训练期 756 天与实际数据可用性

756 天训练期 + 252 天 OOS，从 2020 年开始意味着第一个 OOS fold 要到 2023 年初。对于某些 2019 年以后才上市的标的，fold 数量可能不足 3 个，WFO 结果不可靠。  
**缓解**：`run_wfo.py` 应检查每个标的的可用数据长度，少于 3 个 OOS fold 的标的改用固定参数（`s_final.yaml`）而非 WFO 优化。
