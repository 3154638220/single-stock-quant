### 1.3 关键观测

1. **出场主导收益**：5 只股票的出场原因中 `profit_lock` 占比 >90%，意味着盈利锁定止盈是唯一有效退出机制，其他出场机制（ATR 止损、趋势止损等）几乎从不触发。这既是一个调参过拟合信号，也是一个收益杠杆：若能让更多笔交易正确用上止盈/趋势跟踪出场，收益有提升空间。

## 二、算法不足的详细诊断

### 2.1 信号层：二值状态机的结构性缺陷

**问题一：MACD 交叉是高度滞后的信号**

当前默认模式 `macd_cross` 的逻辑是：`EMA(fast) - EMA(slow)` 差值穿越其 9 日信号线。由于 EMA 对价格变化的反应本身已滞后，再叠加信号线平滑，实际入场通常落后趋势启动 3-8 个交易日。对于趋势性股票这是可接受的，但对于频繁横盘的个股会导致"入场即亏损"的追涨现象。

具体缺陷：
- WFO 网格仅搜索 `macd_fast ∈ {10,12,14}`，`macd_signal ∈ {8,9,10}`，参数范围太窄，未覆盖高频信号（fast=5-8）和低频确认（fast=20-30）的组合空间
- `macd_slow` 硬编码为 26，未纳入 WFO 优化，导致某些股票可能系统性用了次优参数

**问题二：颜色状态机忽略信号强度**

`compute_dktrend` 输出的 `dk_color` 是纯二值（红/绿），`dk_value` 虽然是连续值但在信号过滤中几乎未被使用：
- 入场不区分"刚刚翻红（dk_value=0.001）"和"强势上行（dk_value=0.5）"
- 出场的 `dk_fade_exit_n` 参数（连续 N 天 dk_value 缩小则退出）在当前最优配置中 `dk_fade_exit_n=0`，说明该机制未被激活
- 缺少对信号置信度的概率化表达，无法做基于置信度的仓位缩放

**问题三：多模式共识机制削减交易频率但不提升质量**

`compute_consensus_trend` 要求 3 种模式中至少 2 种同向，逻辑上合理，但：
- 3 种模式（MACD / MA / Boll）的参数高度相关（均基于 close 均线），并非独立信号
- 共识过滤会显著减少交易笔数（从 ~50 笔到 ~30 笔），但胜率未必提升
- 目前 selected_single_stock_best 配置仍显式设置 `consensus_n_agree: 2`，是冗余的且可能造成有效交易损失

### 2.2 出场层：单一机制主导的脆弱性

**问题四：profit_lock 参数已过拟合**

`profit_lock_trigger=0.08, profit_lock_trailing=0.04` 组合导致 >90% 的出场都是盈利保护止盈。这意味着：
- 当价格突破 8% 后、任何回落 4% 均出场，不管趋势是否持续
- 在大趋势行情（如 300750 2020-2021 年牛市）中，该参数会过早锁定利润、错过主升浪后半段
- `profit_lock` 的超参数（0.08/0.04）只针对某几只股票在某个样本期进行了优化，不具有跨时期稳定性

**问题五：ATR 止损与 intrapos_dd_limit 功能重叠但均未生效**

- `atr_stop_multiplier=0.0`：ATR 动态止损完全关闭
- `intrapos_dd_limit=0.05`（000783 最优配置）：持仓内回撤 5% 退出，但与 `profit_lock` 逻辑存在竞争，实际触发率取决于行情路径
- `trailing_stop_pct=0.0`：固定比例追踪止损也关闭
- 结果：只有 `stop_loss_pct=0.08` 作为最终保底，但这是硬止损而非盈利保护

**问题六：时间止损逻辑粗糙**

`time_stop_days=30, time_stop_min_return=0.03`：持仓超过 30 天且收益不足 3% 则退出。这一机制的问题：
- 30 天窗口对于趋势型策略是过短的，很多好趋势在第 25-45 天才加速
- 3% 的最低收益门槛与 `profit_lock_trigger=8%` 之间存在空档，可能频繁触发对弱趋势的过早出场

### 2.3 入场层：过滤条件的误用

**问题七：质量评分（signal quality）是规则集而非学习模型**

`compute_signal_quality` 函数对 BUY 信号打 0-100 分，基于 8 个规则：
- +15：run_len ≥ 2
- +15：成交量确认
- +15：共振数 = 3
- +10：市场收益 > 0
- +10：ATR < 中位 ATR
- +10：close > MA20
- +10：MA20 斜率 > 0
- +15：RS_60 > 0

这些规则是人为拍定的权重，未经过对信号后续收益的统计验证。例如：在强势个股上，"ATR > 中位 ATR" 往往伴随突破加速，是好信号而非差信号；但评分系统在此情况下扣 10 分，方向可能是错的。

**问题八：MA120 过滤器误伤价值底部买点**

`require_above_ma120=False` 当前关闭，这是正确的，因为 A 股个股在箱体底部的反转买点往往在 MA120 以下。但注意到某些配置在实验时误开启了此过滤，导致交易数从 ~50 降到 ~30，且并不总是提升胜率。

**问题九：ADX 过滤器的阈值未经验证**

`require_adx_min` 功能存在但 WFO 网格中未搜索过该参数。A 股日频 ADX 的有效趋势阈值通常在 20-30 之间，但不同板块、不同市值股票差异极大。未经验证直接使用固定阈值可能适得其反。

### 2.4 仓位管理层：大量机制关闭

| 机制 | 当前状态 | 问题 |
|---|---|---|
| 波动率目标仓位 | `volatility_target_ann=0.0`（关闭） | 高波动期仓位未缩减，增加回撤 |
| 质量评分缩放 | `quality_score_mode=hard`（硬过滤而非缩放） | 无法利用信号质量做连续仓位调整 |
| 回撤节流 | `drawdown_throttle_enabled=False` | 连续亏损后不降低风险敞口 |
| 风险比例仓位 | `risk_per_trade_pct=0.0`（关闭） | 每笔固定全仓，不按止损距离调整 |
| 指数 MA20 过滤 | `enable_index_ma20_filter=False` | 市场弱势期未降仓 |

上述 5 个机制均有代码实现，但在当前最优配置中全部关闭。这是因为 WFO 在搜索这些参数时产生了不稳定结果（过拟合）。根本原因是这些机制的参数空间太大、WFO 样本太少，优化器找到了局部最优而非真实有效的参数组合。

### 2.5 WFO 框架：样本不足与目标函数偏差

**问题十：OOS fold 数量严重不足**

| 股票 | 数据起始 | WFO folds | OOS 覆盖年数 |
|---|---|---:|---:|
| 000783 | ~2018 | 3 | ~3 年 |
| 其他标的 | ~2020 | 3 | ~2 年 |

3 个 OOS fold 对于评估策略稳定性是远远不够的。Bootstrap Sharpe 置信区间下界为负的根本原因正在于此：有效样本量太小，无法区分 Alpha 和随机噪声。

**问题十一：WFO 目标函数包含隐性偏差**

```python
# 当前目标函数
score = 0.40 * calmar + 0.35 * sharpe + 0.25 * dd_score
score *= reliability  # reliability = min(1.0, n_trades / 20)
```

问题：
- `reliability` 乘数对交易数 < 20 的参数组合施加惩罚，但在实践中，高质量低频信号（例如 7-10 笔/年）的收益可以非常好
- 当 score < 0 时使用 `score / reliability` 放大负分，这对交易少但亏损的组合过度惩罚，使得优化器倾向于交易数多但每笔收益平庸的方案
- Calmar（年化收益/最大回撤）在 max_drawdown 接近 0 时会产生极端大值，破坏得分稳定性（需要在 `_composite_score` 中 clip 处理，当前已 clip 到 2.0，但仍然敏感）

**问题十二：参数网格搜索空间过窄且不对称**

当前 `FOCUSED_PARAM_GRID`：
```python
{"macd_fast": [10, 12, 14], "macd_signal": [8, 9, 10], 
 "profit_lock_trigger": [0.06, 0.08, 0.10], "profit_lock_trailing": [0.03, 0.04, 0.06]}
```

- 只搜索 MACD 参数（快线 + 信号线），慢线（26）和 `min_run_len` 被固定
- 4 个参数 × 3 层 = 81 组合，但核心出场参数（`intrapos_dd_limit`、ATR 止损）未纳入搜索
- 入场过滤参数（ADX、突破确认、成交量阈值）完全不在 WFO 网格中

### 2.6 元标签模型：逻辑回归已触及能力上限

**问题十三：逻辑回归对非线性市场特征拟合能力不足**

`meta_label.py` 使用 Logistic Regression，在每个 WFO train fold 内训练，用于预测"BUY 信号是否值得执行"。

核心限制：
- 逻辑回归假设特征与标签之间是线性分离的；A 股信号质量受多因子非线性交叉影响（高成交量 × 低 ATR × MA 正斜率，三者组合比单独任一更能预测胜率）
- 每个 WFO train fold 的 BUY 信号数通常只有 15-30 个，特征维度约 15-20，逻辑回归在此情况下等同于噪声拟合
- 标签定义仅用 `forward_return > 0`（或加 MAE 约束），未考虑 MFE/MAE 比率、持仓时间等更丰富的收益质量维度

**问题十四：特征工程缺少关键信息**

当前 `FEATURE_COLUMNS` 包含约 15-20 个特征（MA 斜率、ATR、成交量比率、Donchian 突破、RS 相对强度等），但缺失：
- **趋势持续时间**：当前 dk_run_len 进入特征，但未计算趋势年龄的正规化版本（趋势已持续 N 天占历史平均趋势周期的比例）
- **前次交易结果**：最近一次同股票交易的盈亏，用于识别股票近期"手感"
- **板块动量**：同板块近期涨跌幅对个股趋势的影响（`sector_features.py` 已有框架但未集成到元标签特征中）
- **大盘状态细化**：当前只用 60 日收益率判断牛熊，缺少大盘波动率状态（VIX 代理）、成交量异常等维度

### 2.7 代码性能瓶颈

**问题十五：纯 Python 循环制约大规模参数搜索**

`_persistent_price_change_color` 函数用纯 Python 逐行迭代计算颜色状态机，对每个参数组合都需要重新计算。在 WFO 网格搜索时（81 组合 × 3 fold），这个循环会被调用约 250 次，每次处理 1000-2000 行数据，是明显的性能瓶颈。

`_supertrend_lst` 同样用纯 Python 循环计算超级趋势线，性能约为向量化实现的 1/20。

#### P0.2 修正 WFO 目标函数

问题：当前 `reliability = min(1.0, n_trades/20)` 对少交易策略过度惩罚。

修改 `src/backtest/wfo.py` 的 `_composite_score`：

```python
def _composite_score(res, *, train_days=504, ...):
    years = max(train_days / 252.0, 0.25)
    n_per_year = res.n_trades / years
    
    # 放宽最低交易频率到 2笔/年（从 4 放宽）
    if n_per_year < 2:
        return -np.inf
    if n_per_year > 30:
        return -np.inf
    if res.max_drawdown > 0.35:    # 从 0.40 收紧到 0.35
        return -np.inf

    # 新增：总收益作为辅助指标（权重 15%）
    total_ret = np.clip(res.total_return, -0.5, 1.0) if np.isfinite(res.total_return) else -0.5
    calmar = np.clip(res.calmar_ratio, -1.0, 3.0) if np.isfinite(res.calmar_ratio) else -1.0
    sharpe = np.clip(res.sharpe_ratio, -2.0, 3.0) if np.isfinite(res.sharpe_ratio) else -2.0
    dd_score = max(0.0, 1.0 - res.max_drawdown * 2) if np.isfinite(res.max_drawdown) else 0.0
    
    raw_score = 0.35 * calmar + 0.25 * sharpe + 0.15 * dd_score + 0.15 * total_ret + 0.10 * (n_per_year / 10)
    # 可靠性折扣：低于 10 笔开始折扣，但最低保留 30%（从 10% 提高）
    reliability = min(1.0, max(float(res.n_trades), 0.0) / 10.0)
    reliability = max(reliability, 0.30)
    return raw_score * reliability if raw_score >= 0 else raw_score / reliability
```

### P1：出场层重设计（最高收益杠杆）

**核心假设**：当前 profit_lock 参数 (0.08/0.04) 是对训练集的过拟合，大趋势行情中过早兑现导致复利收益损失。

#### P1.1 出场机制组合实验矩阵

对 000783 和 300750（当前最优两只）各跑以下 16 组实验：

#### P3.3 标签定义改进

当前二值标签（`return > 0`）噪声太大，改为三值质量标签：

```python
def _label_quality(forward_return: float, mae: float, threshold: float = 0.03) -> int:
    """
    1（优质）：return > threshold 且 mae < threshold/2
    0（可用）：return > 0 但 mae >= threshold/2，或 0 < return < threshold
    -1（差）：return <= 0
    """
```

只训练区分"优质"vs"差"（忽略"可用"样本），可以显著提升精度（precision），代价是减少训练样本量。

def _run_grid_parallel(combos, df, params_base, bt_kwargs_base, ...):
