## 阶段 2：参数过拟合修复（触发条件：阶段 1 边缘或失败）

**问题根因**：`profit_lock_trigger` 和 `profit_lock_trailing` 是 IS 全样本实验中选出的最优参数，同时又放入 WFO 网格——每个 fold 的 IS 会重新找这两个参数的最优值，OOS 无法泛化。

### 方案 A：固定出场参数（推荐首选）

使用 `configs/wfo_stable.yaml`（已存在）：网格只含 `macd_fast` × `macd_signal`（9 个组合），利润保护参数固定为 IS 最优值 `0.08/0.04`。

验证逻辑：若 `wfo_stable.yaml` 的 OOS Sharpe 明显优于 `s_final_wfo.yaml`，则过拟合假设成立，使用 stable 配置。

### 方案 B：嵌套 WFO（Honest OOS）

```bash
python scripts/run_wfo.py \
  --symbol 300750 \
  --config configs/s_final_wfo.yaml \
  --nested \
  --train-days 756 --oos-days 252 \
  --inner-train-days 504 --inner-oos-days 126 \
  --export-results \
  --output data/output/experiments/WFO_nested_300750/
```

嵌套 WFO 在外层 OOS fold 内再做内层 WFO 选参，是最严格的防过拟合方法，但计算量增加约 5 倍。

### 方案 C：放弃 WFO，使用固定参数 + Symbol 过滤

若 WFO 在多种配置下始终 OOS < IS，放弃参数优化。统一使用 `s_final.yaml` 固定参数，通过阶段 4 的 Symbol 适用性评分控制质量。这是"最少有效变更"原则的极致体现。

**决策标准**：若方案 C（固定参数）的 OOS 结果不劣于方案 A/B，直接采用方案 C，减少系统复杂度。

## 阶段 3：GBM Meta-label WFO 验证

**前提**：阶段 1 或 2 已确定基线 WFO 配置  
**目标**：验证 GBM + label_v4 + 日级样本是否在 OOS 中提供增量

### 3.1 实验设计（三向对比）

```bash
BASE_CFG="configs/wfo_stable.yaml"   # 由阶段1/2确定的最优基线配置

# E_ML_A：logistic + profit_aware（当前基线）
python scripts/run_wfo.py --symbol 300750 \
  --config $BASE_CFG \
  --enable-meta-label --meta-model-type logistic \
  --meta-label-type profit_aware \
  --output data/output/experiments/E_ML_A_logistic_300750/

# E_ML_B：GBM + label_v4（新方案）
python scripts/run_wfo.py --symbol 300750 \
  --config $BASE_CFG \
  --enable-meta-label --meta-model-type gbm \
  --meta-label-type label_v4 \
  --output data/output/experiments/E_ML_B_gbm_300750/

# E_ML_C：GBM + label_v4 + 日级样本（最丰富特征）
python scripts/run_wfo.py --symbol 300750 \
  --config $BASE_CFG \
  --enable-meta-label --meta-model-type gbm \
  --meta-label-type label_v4 \
  --meta-use-daily-samples \
  --output data/output/experiments/E_ML_C_gbm_daily_300750/
```

### 3.2 关键注意事项

**日级样本自相关问题**：`build_daily_labels` 生成的日级特征高度自相关（DK 趋势状态缓慢变化）。需确认 WFO 内部的 meta-label 训练使用纯时间切分而非随机切分：

```bash
grep -n "TimeSeriesSplit\|cross_val\|train_test_split" \
  src/models/meta_label.py src/models/meta_label_gbm.py src/backtest/wfo.py
```

若发现任何随机切分，必须改为 `TimeSeriesSplit`。

**forward_days 与 OOS 窗口协调**：`label_v4` 的 `forward_days=10` 意味着最后 10 个交易日的标签需要未来数据——WFO 的 IS 尾部 10 天会有前视偏差。需确认 WFO 切割时留有 buffer：

```python
# wfo.py 中的 IS 切割应为：
is_end = fold_start + train_days - forward_days - 1  # buffer
```

### 3.3 验收标准

| 指标 | GBM 通过标准 | 说明 |
|---|---|---|
| OOS Sharpe | > 无 meta-label 基线 | 有增量才值得复杂度代价 |
| p_win top/bottom 5 分位 forward return 差 | > 0（5日和10日） | 信号排序有意义 |
| Meta-label precision（OOS） | ≥ 0.55 | 超过随机（基础率通常 0.45–0.50） |
| 信号过滤后 trades 减少比例 | 20%–50% | 过滤太少无效，太多信号不足 |

**若 GBM 无增量**：跳过，继续使用无 meta-label 配置。复杂度不带来收益就是负担。

## 三、已知风险与缓解措施

### 风险 1：利润保护参数过拟合（最高优先级）

`profit_lock_trigger=0.08 / trailing=0.04` 源自 IS 全样本优化。WFO 网格重复优化这两个参数会叠加过拟合。

**缓解**：阶段 1 同时运行 `s_final_wfo.yaml`（参数入网格）和 `wfo_stable.yaml`（参数固定），对比 OOS 结果。若 stable 更优，采用 stable 配置进入后续阶段。

### 风险 2：GBM 日级样本自相关

DK 趋势特征（`dk_run_len`、`dk_value`）日内变化极小，连续样本高度相关。内部的 meta-label 模型若用随机切分评估，会高估精度 10–20 个百分点。

**缓解**：代码审查确认所有内部评估使用 `TimeSeriesSplit`；WFO 时间切分已实现，但要检查 `_fit_meta_model_for_fold` 中的训练逻辑。

### 风险 3：数据可用性约束导致 Fold 数不足

WFO 配置为 756 天训练 + 252 天 OOS，2020 年起的第一个 OOS fold 到 2023 年初。对于 2020 年后上市的标的（如部分科创板），fold 数量可能 ≤ 2，结果不可靠。

**缓解**：在 `run_batch_backtest.py` 中增加检查：

```python
if n_folds < 3:
    warnings.warn(f"{symbol}: 仅 {n_folds} 个 OOS fold，结果不可靠，跳过 WFO，改用固定参数")
    # fall back to s_final.yaml fixed params
```

### 风险 4：AkShare 接口不稳定

AkShare 是社区维护的免费接口，历史上存在不定期变更或限流。生产环境依赖单一数据源是脆弱的。

**缓解**：
- `akshare_resilience.py` 已实现重试逻辑，确认 `max_retries=5, backoff=2`
- 部署时添加每日数据完整性告警
- 中期考虑：增加备用数据源（baostock 或 tushare）作为 fallback

### 风险 5：SE3 入场过滤降级的诊断不确定性

SE3 全部降级可能是信号减少后 IS Sharpe 标准误增大导致的假阴性（真实效果被噪声掩盖），而非入场机制本身无价值。

**缓解**：在 E_SINGLE 全量验收后，对 SE3a（Donchian 突破过滤）单独做 OOS permutation test：

```bash
python -c "
from src.backtest.permutation_test import run_permutation_test
# ...（实现后运行）
"
```

若 permutation p-value < 0.10，重新考虑 SE3a 的 OOS 价值。
