## 三、Phase H：T2 快熊防护（最高优先级）

### H-1：双速市场状态检测（核心新增）

**问题**：单一 MA120 无法同时处理两种熊市模式：
- **慢熊**（T4 新能源 2022）：板块轮动，下跌缓慢，MA120 有效
- **快熊**（T2 贸易战 2018）：系统性快速下跌，MA120 反应严重滞后

**解决方案**：引入双速判断，两个条件满足任意一个即视为熊市：

```python
# 新增参数（在 run_rotation_backtest 签名中）
regime_fast_ma_period: int = 60,    # 快速熊市检测（约 3 个月，捕捉快熊）
regime_slow_ma_period: int = 120,   # 慢熊检测（约 6 个月，捕捉慢熊，兼容现有逻辑）

# 判断逻辑（替换现有单一 MA120 判断）
ma_fast = idx_close.rolling(regime_fast_ma_period, min_periods=regime_fast_ma_period // 2).mean()
ma_slow = idx_close.rolling(regime_slow_ma_period, min_periods=regime_slow_ma_period // 2).mean()

slope_fast = ma_fast.diff(5)   # 5 日变化（约 1 周）
slope_slow = ma_slow.diff(10)  # 10 日变化（约 2 周）

# 快熊：价格大幅跌破快速均线且均线向下
is_bear_fast = (
    current_close < ma_fast.iloc[i] * 0.97 and  # 跌破 MA60 的 3%（防止假信号）
    slope_fast.iloc[i] < 0                       # MA60 向下倾斜
)

# 慢熊：价格跌破慢速均线且均线向下（兼容现有 T4 防护）
is_bear_slow = (
    current_close < ma_slow.iloc[i] and
    slope_slow.iloc[i] < 0
)

is_bear = is_bear_fast or is_bear_slow
```

**实现位置**：`src/backtest/rotation.py`，在现有 `market_regime_bearish` 预计算逻辑中替换。

**参数**：
- `regime_fast_ma_period`（新增）：默认 60
- `regime_slow_ma_period`（替换现有 `regime_ma_period=120`，保留向后兼容接口）
- `regime_fast_threshold`（新增）：快熊判断的价格偏离阈值，默认 0.97（跌破 MA60 3% 才触发）

**脚本侧**：`run_rotation.py` 和 `run_stress_test.py` 新增 `--regime-fast-ma-period`、`--regime-slow-ma-period`、`--regime-fast-threshold` 参数。

**向后兼容性**：
- 若仅传入 `regime_ma_period`（旧接口），自动映射至 `regime_slow_ma_period`
- 若显式传入 `regime_fast_ma_period=0`，等价于禁用快熊检测（退化为 Round 6 行为）

### H-2：指数回撤触发器（第二防线）

**问题**：均线类信号本质上是趋势滞后确认，在下跌开始时都有延迟。

**解决方案**：增加基于价格回撤幅度的触发器。当 CSI300 从近期高点回撤超过阈值时，立即激活防护，无需等待均线斜率。

```python
# 新增参数
regime_drawdown_trigger: float = 0.0,   # 0.0 = 禁用，0.15 = 回撤 15% 触发

# 判断逻辑（在双速判断后追加）
if regime_drawdown_trigger > 0:
    rolling_peak = idx_close.rolling(regime_drawdown_lookback, min_periods=20).max()
    drawdown_from_peak = (idx_close / rolling_peak - 1.0)
    is_bear_drawdown = drawdown_from_peak.iloc[i] < -regime_drawdown_trigger
    is_bear = is_bear or is_bear_drawdown
```

**参数**：
- `regime_drawdown_trigger`（新增）：默认 0.0（禁用），推荐测试值 0.12、0.15
- `regime_drawdown_lookback`（新增）：滚动高点计算窗口，默认 60 交易日

**注意**：回撤触发器比均线触发器更灵敏，可能产生更多假信号（短期回调）。需在以下测试中验证假信号代价：
- T1（2015 年崩盘后 Q4 反弹期间）
- T5（近期牛市期间多次 5-10% 的正常回调）

### H-3：组合权益曲线级回撤限制（第三防线）

**问题**：前两个防线依赖 CSI300 指数数据。若指数数据不可用（历史数据缺失、未来实盘数据延迟），或者个股跌幅显著超过指数，需要一个不依赖外部数据的最后防线。

**解决方案**：在轮动引擎内部追踪投资组合权益峰值，当当前权益低于历史峰值 X% 时强制清仓至现金。

**实现位置**：`src/backtest/rotation.py`，主循环中每日更新权益并检查。

```python
# 新增参数
portfolio_dd_limit: float = 0.0,  # 0.0 = 禁用，0.20 = 权益回撤超 20% 清仓

# 主循环内（在市场门控检查后）
if portfolio_dd_limit > 0:
    equity_peak = max(equity_peak, current_equity)
    equity_drawdown = current_equity / equity_peak - 1.0
    if equity_drawdown < -portfolio_dd_limit:
        # 强制将 effective_top_n 设为 0（触发清仓，不等待 regime 恢复）
        effective_top_n = 0
        force_rebalance = True  # 覆盖现有 force_rebalance 计算
        portfolio_dd_triggered = True  # 记录日志
```

**差异于现有 `drawdown_throttle_enabled`**：现有参数仅在 `run_single_stock_backtest()` 中有效（单标的），轮动引擎 `run_rotation_backtest()` 从未使用此参数。这是新增在轮动层面的同类机制。

**参数**：
- `portfolio_dd_limit`（新增）：默认 0.0（禁用），推荐测试值 0.18、0.20、0.25
- 与市场门控的优先级：portfolio_dd_limit 是 OR 关系（任一触发即清仓），独立于市场门控

## 四、Phase I：MDD 结构性压缩

Phase H 解决了快熊的入场/出场速度问题，Phase I 解决**已入场时的持仓风险控制**问题。即使进入一段趋势行情，单笔持仓的回撤也可能很大（当前单笔 ATR 止损存在于 `single_stock.py` 但轮动引擎**并未启用 ATR 止损**）。

### I-1：轮动引擎个股止损机制激活

**现状**：轮动引擎（`rotation.py`）有基本的 profit_lock 逻辑，但没有硬性止损和 ATR 止损。从代码中可见 `_check_exit_conditions()` 函数处理 profit_lock，但缺少固定止损和 ATR 跟踪止损。

**新增机制**：在轮动引擎的个股退出检查中，新增以下参数：

```python
# run_rotation_backtest() 新增参数
rotation_stop_loss_pct: float = 0.0,      # 固定止损（0.0=禁用），推荐 0.10
rotation_atr_trailing_mult: float = 0.0,  # ATR 跟踪止损倍数（0.0=禁用），推荐 2.0
rotation_atr_period: int = 14,            # ATR 计算周期
rotation_atr_min_gain: float = 0.05,      # ATR 止损激活的最低浮盈（0.05=5%）
```

**实现位置**：`src/backtest/rotation.py`，`_check_exit_conditions()` 函数，对齐 `single_stock.py` 中的同类逻辑。

**注意**：轮动引擎中已有 `profit_lock_trigger/trailing`，新增内容仅为**止损**（防止亏损扩大），而非修改 profit_lock（保护利润）逻辑。两套机制互不冲突。

---

### I-2：波动率目标仓位调整

**现状**：`vol_inverse` 仓位分配（已实现，第五轮引入）按波动率反比分配权重，但仅在持仓池内部再分配，不控制总体市场暴露。

**新增机制**：当组合整体实现波动率（过去 20 日日收益标准差 × √252）超过目标波动率的 1.5 倍时，对所有持仓同比例缩减：

```python
# run_rotation_backtest() 新增参数
volatility_target_ann: float = 0.0,    # 年化目标波动率（0.0=禁用），推荐 0.25
volatility_scale_floor: float = 0.30,  # 最低保留仓位比例（0.30=最多缩减 70%）
```

**实现逻辑**：
```python
if volatility_target_ann > 0 and len(daily_returns) >= 20:
    realized_vol = np.std(daily_returns[-20:]) * np.sqrt(252)
    vol_scale = min(1.0, volatility_target_ann / max(realized_vol, 1e-6))
    vol_scale = max(vol_scale, volatility_scale_floor)
    # 调整 allocation 时乘以 vol_scale
    allocation = base_allocation * vol_scale
```

## 五、Phase J：X2 真实多 Alpha 验证

### J-1：轮动引擎支持 per-symbol DK 参数

**现状**：轮动引擎对所有股票使用同一套 `DKTrendParams`。但不同股票的趋势特性可能差异很大：
- **300750（宁德时代）**：高波动成长股，MACD 快速信号适合
- **600036（招行）**：银行慢牛，MACD 信号频率过高，Donchian 突破更适合
- **000858（五粮液）**：白酒周期股，介于两者之间

**实现**：`run_rotation_backtest()` 新增 `symbol_params: dict[str, DKTrendParams] | None = None` 参数，优先使用 per-symbol 参数，回退到全局 `trend_params`。

```python
# run_rotation_backtest() 新增
symbol_params: dict[str, DKTrendParams] | None = None,

# _compute_trend() 调用时
effective_params = (symbol_params or {}).get(sym, params)
trend = _compute_trend(df, effective_params, ...)
```

**脚本侧**：新增 `configs/symbol_params.yaml` 支持，格式：

```yaml
# configs/symbol_params.yaml
symbol_params:
  "300750":
    mode: macd_cross
    macd_fast: 12
    macd_slow: 26
    macd_signal: 9
  "600036":
    mode: donchian_breakout
    donchian_entry_window: 30
    donchian_exit_window: 15
  "000858":
    mode: donchian_breakout
    donchian_entry_window: 25

```
