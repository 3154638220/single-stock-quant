# 模型效果提升计划

**项目**：`single-stock-quant`
**日期**：2026-05-13
**前置状态**：生产链路已就绪，输入股票代码可返回信号与回测结果。
**目标**：从信号质量、风险控制、参数寻优、评估严谨性四个维度系统性地提升模型的实际回测/实盘绩效。

---

## 总体思路

当前系统存在一个核心矛盾：**三种 mode（`macd_cross` / `ma_cross` / `boll_trend`）均使用固定参数，对所有股票一视同仁**。提升效果的关键路径是：

```
固定参数单指标  →  多信号过滤  →  走前向参数寻优  →  加入风控  →  跨股票严格评估
```

下面按优先级分为四个阶段，每个阶段独立可交付，不依赖后续阶段。

## 阶段一：信号质量增强（高收益、低风险）

### 1-1 成交量确认过滤器

**问题**：当前信号纯价格驱动，量价背离时经常假突破。

**改动位置**：`src/signals/generator.py`，在 `generate_signals()` 中新增可选的 `volume_filter` 参数。

**规则**：
- BUY 信号触发日的成交量须 ≥ 近 N 日均量的 `volume_ratio_min`（默认 N=20，ratio=1.0）。
- 不满足则信号降级为 HOLD，下一日重新判断。

```python
# config.yaml 新增字段
signal_filter:
  volume_confirm: true
  volume_lookback: 20
  volume_ratio_min: 1.0
```

**预期效果**：减少缩量假突破，提高单次交易胜率（历史验证通常 +3–8% 胜率）。

---

### 1-2 多指标共振过滤（Multi-Mode Consensus）

**问题**：单一指标噪声高，不同 mode 互相矛盾时无依据。

**改动位置**：新增 `src/signals/consensus.py`。

**规则**：
```
N_AGREE = 指定阈值（默认 2，即三个 mode 中至少 2 个为红色才触发 BUY）
```

实现逻辑：
1. 对同一股票并行计算三种 mode 的 `dk_color`。
2. 当红色 mode 数 ≥ `n_agree` 时，发出 BUY；绿色 mode 数 ≥ `n_agree` 时，发出 SELL。
3. 默认 `n_agree=2`，可配置。

```python
# config.yaml 新增字段
trend_signal:
  consensus_n_agree: 2   # 需几个 mode 共振才发信号
```

**预期效果**：大幅降低假信号，代价是减少交易频次（适合波动较小、趋势明显的标的）。

---

### 1-3 市场趋势过滤（大盘保护层）

**问题**：A 股系统性下跌时，单股多头信号亏损概率极高，但当前策略无保护。

**改动位置**：`src/backtest/single_stock.py`，在 `run_single_stock_backtest()` 中加入可选的 `index_filter` 参数；复用已有的 `risk_metrics.py` 中 `risk_off_multiplier_from_index()`。

**规则**：
- 若 CSI300（`510300`）近 N 个交易日累计跌幅超过阈值（默认 N=10，跌幅 >5%），禁止开仓（`risk_off_factor=0`）。
- 已有的 `risk_off_multiplier_from_index()` 函数已实现此逻辑，直接接入回测循环即可。

```python
# config.yaml 中已有 risk 节点，补充：
risk:
  enable_index_filter: true
  benchmark_symbol: "510300"
  extreme_lookback_days: 10
  extreme_drop_threshold: 0.05
  risk_off_factor: 0.0
```

**预期效果**：规避 2015、2018、2022 等系统性大熊市中的大额亏损，显著改善最大回撤指标。

## 阶段二：止损机制（降回撤、必要功能）

### 2-1 固定百分比止损

**问题**：当前策略只有趋势信号出场，无兜底止损，极端行情下单笔亏损可超过 20%。

**改动位置**：`src/backtest/single_stock.py`，在持仓循环中新增止损判断；同时在 `SingleStockBacktestResult` 中增加 `stop_loss_exits` 计数字段。

**规则**：
```
若当日收盘价 / 买入价 - 1 < -stop_loss_pct，次日开盘强制平仓
exit_reason = "stop_loss"
```

```python
# config.yaml
backtest:
  stop_loss_pct: 0.08    # 亏损 8% 止损，0 表示关闭
```

---

### 2-2 追踪止损（可选增强）

在 2-1 基础上，改用从持仓最高净值往下追踪：

```

```

```python
# config.yaml

  trailing_stop_pct: 0.10   # 从持仓高点回落 10% 止损，0 表示关闭
```

**建议**：先上 2-1 固定止损（简单可靠），2-2 作为对比实验。

## 阶段三：参数寻优（避免过拟合的正确姿势）

> **警告**：参数寻优若直接在全历史上 grid search，必然过拟合。本阶段强制使用**走前向验证（Walk-Forward Optimization, WFO）**。

### 3-1 WFO 框架

**新增文件**：`src/backtest/wfo.py`

**核心逻辑**：
```
训练窗口：前 T 个交易日（默认 504，约 2 年）
测试窗口：后 M 个交易日（默认 126，约半年）
步进方式：每次向前滑动 M 个交易日（expanding 或 rolling，可配置）

对每个训练窗口：
  grid_search(params_grid) → 选 Sharpe 最高的参数组合
  在对应 OOS 窗口执行 → 记录 OOS 绩效

最终：拼接所有 OOS 段的日收益序列 → 计算整体绩效
```

**参数搜索空间**（默认，可在 config 中覆盖）：

```python
PARAM_GRID = {
    "macd_fast":   [8, 10, 12, 14],
    "macd_slow":   [22, 26, 30],
    "macd_signal": [7, 9, 11],
}
```

**使用方式**：

```bash
python scripts/run_wfo.py --symbol 600930 \
    --train-days 504 --oos-days 126 \
    --mode macd_cross \
    --export-results
```

### 3-3 参数稳定性检验

**目的**：判断"最优参数"是否只是噪声。

在 WFO 输出中额外记录：

- IS Sharpe vs OOS Sharpe 的相关系数（高相关 → 参数真正有效）

## 阶段四：评估严谨性提升

### 4-1 多标的横截面验证

**问题**：目前只在 600930（华电新能）上验证，结论的代表性存疑。

**新增脚本**：`scripts/run_batch_backtest.py`

```bash
# 对 watchlist 中所有标的跑回测，输出汇总报告
python scripts/run_batch_backtest.py \
    --watchlist configs/watchlist.txt \
    --start 2020-01-01 \
    --mode macd_cross \
    --export-summary results/batch_summary.csv
```

**输出**：每只股票一行，包含 Sharpe / Calmar / 最大回撤 / 胜率 / 交易次数。

**验收标准**：20+ 只股票中，Sharpe > 0 的比例 > 60%；中位数 Calmar > 0.5。

---

### 4-2 基准比较（Alpha 评估）

**问题**：当前绩效报告没有对比基准，无法判断策略是否创造超额收益。

**改动位置**：`src/backtest/single_stock.py` 中 `SingleStockBacktestResult` 新增字段；`scripts/run_backtest_single.py` 输出时增加对比列。

新增指标：
- **超额收益**：策略年化收益 − 个股买持年化收益
- **信息比率**：超额收益均值 / 超额收益标准差 × √252
- **Beta**（相对 CSI300）

---

### 4-3 实现 DSR（Deflated Sharpe Ratio）

**问题**：`performance_panel.py` 中 `dsr` 和 `dsr_pvalue` 字段已声明但未实现（值为 `nan`）。

**实现公式**（Bailey & López de Prado, 2014）：

```
DSR = Φ[ (SR_hat - SR_ref) × √(T-1) / √(1 - γ₃×SR_hat + (γ₄-1)/4×SR_hat²) ]
```

其中 SR_ref 由多次 trial 数量折算，γ₃/γ₄ 为收益的偏度和峰度。

**意义**：当参数搜索次数 > 1 时，DSR 自动对多重检验进行惩罚，是比原始 Sharpe 更可信的绩效衡量。

## 不纳入本次计划的项目

| 功能 | 排除原因 |
|---|---|
| 机器学习模型（LSTM/XGBoost 择时） | 当前数据量不足以训练，过拟合风险极高 |
| 分钟级高频信号 | 需付费数据源，成本/收益不合算 |
| 做空/融券 | A 股散户限制多，超出系统定位 |
| 仓位分散（同时持多只）| 改变系统单股定位，另起规划 |
| 实时推仓到券商 API | 合规与技术复杂度高，另起规划 |
