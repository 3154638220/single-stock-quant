## 二、根本原因诊断（框架层面）

### 2.1 三条结构性障碍

#### 障碍 A：日线 MACD 在 A 股产生大量噪声信号

MACD histogram 是价格的二阶导数，在 A 股振荡市中每年会产生 4-8 次 BUY 信号，但真正能转化为持续趋势的只有 1-3 次。现有框架试图用过滤器区分\"好信号\"和\"坏信号\"，但加法质量评分证明这是行不通的——个股日线 MACD 信号质量不具备稳定可预测性。

**根本问题**：在日线频率上，噪声太多，过滤器成本太高（每个过滤器都会丢弃部分好信号），净效果为负。

#### 障碍 B：WFO 8-fold 对单标的策略的统计稳定性要求过高

8 个 OOS fold × 每 fold 约 0.5 年 = 4 年 OOS 测试。一只股票在 4 年内的市场环境可能跨越牛市、熊市、震荡市。要求同一套参数在所有环境下都能达标，是极高的要求——尤其是对只有 3-33 笔 OOS 交易的策略，统计上基本不可能稳健通过。

**根本问题**：单标的 + 单参数集 + 8-fold 严格 WFO = 过高的稳定性要求，需要更多有效信号来分散。

#### 障碍 C：candidate pool 评分系统失真

`_trend_quality_score` 因 DataFrame 索引未重置而对几乎所有股票输出 0.0，该维度权重为 30%。这意味着所有标的的 eligibility 评分最高只能达到理论满分的 70%（上限约 70 分），而 `green` 门槛是 60 分，实际只有少数股票的 rolling_sharpe + signal_freq + liquidity 组合超过 86 分（才能在 70% 权重下过线）。评分体系失真导致了虚假的\"候选不足\"——真实的候选库可能比现在大得多。

### P0-A：修复 `_trend_quality_score` 索引 Bug（30 分钟，零风险）

**Bug 定位**：`scripts/score_symbol_eligibility.py`，`_trend_quality_score` 函数。

**Bug 原因**：

```python
# 当前代码（有 Bug）
close = pd.to_numeric(df["close"], errors="coerce")
rising = (close.diff() > 0).values   # numpy 数组，len = df 行数（如 200）

df_dates = pd.to_datetime(df["trade_date"]).dt.normalize()
for d in red_indices:
    pos = df_dates[df_dates == d].index   # 返回 df 的原始整数标签（如 350）
    if len(pos) > 0:
        i = pos[0]                         # i = 350
        if i > 0 and i < len(rising):      # 350 < 200 为 False → 永不追加
            aligned.append(rising[i])
```

**根源**：`data[data["symbol"] == symbol].copy()` 过滤后 DataFrame 保留原始整数索引（如第 350-550 行），但 `rising` 是按行数计的 numpy 数组（0-199），`i = 350` 超过 `len(rising) = 200`，条件永远为 False，`aligned` 列表始终为空，函数始终返回 0.0。

**修复方案**（5 行，完全向后兼容）：

```python
def _trend_quality_score(df: pd.DataFrame, params: DKTrendParams) -> float:
    """Fraction of DK red days where close > previous close (price rising)."""
    # FIX: reset index so positional access via numpy array is valid
    df = df.reset_index(drop=True)          # ← 新增这一行
    trend = compute_dktrend(df, params)
    red_mask = trend["dk_color"] == "red"
    if red_mask.sum() < 10:
        return 0.0
    close = pd.to_numeric(df["close"], errors="coerce")
    rising = (close.diff() > 0).values
    red_indices = trend.index[red_mask]
    df_dates = pd.to_datetime(df["trade_date"]).dt.normalize().reset_index(drop=True)
    aligned = []
    for d in red_indices:
        pos_list = df_dates[df_dates == d].index.tolist()
        if pos_list:
            i = pos_list[0]
            if 0 < i < len(rising):
                aligned.append(rising[i])
    if not aligned:
        return 0.0
    return float(np.mean(aligned))
```

**验收标准**：对 watchlist_25 重新运行 eligibility，`trend_quality` 列应有非零值（预期多数股票在 0.50-0.70 之间）。

### P1-B：周线信号框架原型实验

**核心假设**：将 MACD 或 Donchian 信号从日线提升至周线，可以自然过滤短期噪声，产生更少但更高质量的信号。基于 A 股历史数据：

- 日线 MACD BUY 信号：000783 年均约 6-8 次，300750 年均约 8-12 次
- 周线 MACD BUY 信号（预期）：年均约 2-4 次，但每次持续性更强

**已有基础**：
- `src/features/weekly_trend.py` 已实现日线聚合为周 OHLCV（按 W-FRI 周期）
- `compute_weekly_trend_state()` 输出每日对应的周线趋势状态
- 缺少的是：将周线 OHLCV 直接喂入 `compute_dktrend()` 或 `compute_donchian_trend()` 的完整流水线

#### B.1 最小可行实现（约 2-3 小时代码量）

**方案 A（周线信号 + 日线执行）**：
- 在信号生成层，将日线 OHLCV 聚合为周线（W-FRI），在周线上计算 MACD/Donchian 信号
- 将周线信号映射回日线（信号周的下周一开盘执行）
- 持仓管理仍用日线价格（止损、止盈判断）
- 优点：可直接复用现有 `single_stock.py` 的持仓管理；缺点：入场时间有一定滞后

**方案 B（`require_weekly_bullish` 复合过滤）**：
- 已有参数 `require_weekly_bullish`（要求周线趋势为多头才允许日线入场）
- 将此参数纳入 WFO 网格测试：`require_weekly_bullish: [true, false]`
- 实际上是将周线状态作为日线信号的门控条件
- 优点：代码改动极少，可立即测试；缺点：仍以日线信号为主，周线只是过滤器

**建议路径**：先测方案 B（1 小时），如有正向结果再开发方案 A。

**方案 B 实验配置**（在 `wfo_000783.yaml` 和 `wfo_300750.yaml` 的 fast_grid 新增）：

```yaml
fast_grid:
  ...
  require_weekly_bullish: [true, false]
  weekly_ma_fast: [5]
  weekly_ma_slow: [13]
```

**验收标准**：`require_weekly_bullish=true` 配置相比对照组：
- 000783：OOS 交易数不减少（周线过滤不应进一步降低已极低的频率）
- 300750：OOS MDD 降低 ≥ 3%（周线牛市状态门控应过滤趋势末期入场）

### P2-A：多标的轮动框架原型（战略布局）

**战略价值**：本轮所有单标的实验的共同问题是\"单笔策略稳定性极低\"。如果同时运行 5-8 只不同行业的标的，每周选择信号最强的 1-2 只持仓，则：
1. OOS 有效交易数从 3-39 笔增加到可能 20-50 笔（分布在不同标的）
2. 单一行业崩盘（如 2022 年新能源）对整体影响降低
3. WFO 评估的有效样本增大，统计置信度提高

**注意**：这是框架性探索，不应立即推翻现有架构，而是作为平行路径评估。

#### A.1 简单相对动量轮动规则

**原型设计**（最小可行版）：

```python
# 每周末（或每个 DK 信号日）：
# 1. 对所有 eligible 股票计算过去 20 日收益（相对 CSI300）
# 2. 选取 RS20 最高的 1-2 只持有下周
# 3. 持仓期间用现有 ATR 追踪止损管理风险
```

**代码基础**：
- `require_positive_rs60` 的 RS 计算逻辑已在 `single_stock.py` 入场过滤链中实现
- 需新增的是：跨标的的轮动调度器（约 100-150 行新代码）
- DuckDB 已有多标的数据，数据层无需改动

#### A.2 评估指标调整

多标的轮动的 WFO 评估需要特殊处理：
- 同期多只标的同时持仓时的资金分配（均等权重 vs 动量权重）
- 换仓成本（转换期的交易摩擦）
- 风险对冲：同一板块两只标的不同时持仓

**本轮任务**（仅原型）：为 000783 + 300750 + 最多 2 只 P1 新候选设计简单轮动规则，手工对照分析（不纳入 WFO 框架），评估概念可行性后再决定是否开发完整系统。

### P3：signal_quality 评分彻底重建（低优先级）

**前提**：P0 + P1 + P2 均无法使至少 2 只标的达标时，才启动本计划。

**现有问题**：三轮实验均证明加法评分（0-100 分）与前向收益无关甚至负相关。

**新方向**：放弃加法评分，转向**结构性二元门控**：

```python
# 新的入场许可逻辑（替代 quality_score）
def entry_permitted(signal_row, close, ma120, rs60, adx, weekly_state) -> bool:
    """
    不再给信号打分，而是设置明确的入场条件组合。
    每个条件必须有独立统计证据（Mann-Whitney p < 0.10）。
    """
    conditions = []
    if require_above_ma120:
        conditions.append(close > ma120)          # 半年趋势方向正确
    if require_positive_rs60:
        conditions.append(rs60 > 0)               # 股票跑赢指数
    if require_weekly_bullish:
        conditions.append(weekly_state == "bullish")  # 周线趋势确认
    # 入场需要所有指定条件同时满足（AND 逻辑，不是加权评分）
    return all(conditions)
```

这实际上已是当前代码中 `require_*` 参数的逻辑——区别在于**彻底删除 `quality_score` 相关代码**（`min_quality_score`、`quality_score_mode`、`compute_signal_quality` 函数），减少混淆和维护负担。

**本轮任务**：不执行，仅记录方向，等 P0-P2 结论后决策。

| OOS Sharpe | 0.77 | 0.29 | -0.48 |
| OOS MDD | 24.81% | 32.45% | +7.64% |
| Param Drift | 0.267 | 0.538 | +0.271 |

**根因分析（第二轮）**：即使移除了 exit=0，全网格仍然严重劣于 fast_grid。原因：
1. **MACD 参数变化是主因**：fast_grid 固定 MACD=(12,26,9)，全网格在 7 种不同 MACD 组合间切换，每 fold 选择不同的 (macd_fast, macd_slow, macd_signal) 以拟合训练期噪声
2. fast_grid 中大多数 fold 选择相同参数（高稳定性），全网格中每 fold 选择不同参数（低稳定性）
3. **param drift 翻倍**（0.267→0.538）直接反映了这一点

**核心教训**：在单只股票上，MACD 参数的自由度越多，过拟合越严重。日线 MACD 信号本身噪声大，优化器通过改变 MACD 参数来拟合噪声，而非找到真正稳健的趋势参数。

**决策**：300750 降级为「难度案例」。fast_grid 的 14.04%/24.81% 是当前框架下的上限。Calmar=0.57 < 0.60 且 MDD=24.81% > 22%，两项均差，停止继续深化。

### 12.2 X1：多标的轮动框架 ✅✅（突破性结果）

**时间**：2026-05-19  
**新增文件**：
- `src/backtest/rotation.py`（~300 行，轮动引擎核心）
- `scripts/run_rotation.py`（CLI 入口）

**核心设计**：
- 同时计算 N 只股票的 MACD 趋势信号
- 每 M 天（默认 5=周度，10=双周度）按趋势强度排序
- 持有排名前 K 只（默认 2 只），等权分配
- 共用一套退出参数（ATR 追踪、intrapos DD、profit lock、time stop）
- 当持仓股票跌出前 K 名或被信号退出时，自动轮换至新标的

**关键洞察**：轮动框架不做 WFO 参数优化——所有股票共用固定参数。这彻底消除了 IS 优化器过拟合问题（单标的 WFO 的核心失败模式）。

#### 12.2.1 全周期回测（2018-2026）

| 配置 | 年化 | Sharpe | MDD | Calmar | 交易数 |
|---|---|---|---|---|---|
| 5 只（含 300750），Donchian，周度 | 14.06% | 0.61 | 28.79% | 0.49 | 404 |
| 5 只（含 300750），MACD，周度 | 21.74% | 0.83 | 28.08% | 0.77 | 385 |
| **3 只（300750+601857+601088），MACD，周度** | **24.92%** | **1.03** | **22.06%** | **1.13** | **273** |
| 3 只（300750+601857+601088），MACD，双周度 | 28.35% | 1.13 | 24.92% | 1.14 | 242 |
| 5 只（不含 300750），MACD，双周度 | 6.84% | 0.39 | 44.06% | 0.16 | 319 |

**关键发现**：
1. **300750 是 alpha 引擎**：去除 300750 后年化从 21.74% 暴跌至 6.84%。轮动框架本身不创造 alpha，而是更有效地捕获现有 alpha。
2. **少即是多**：3 只最优标的 > 5 只混合标的。加入弱势股票（600519 慢牛、000001 银行）拖累收益而不改善 MDD。
3. **MACD > Donchian**：在所有轮动配置下，MACD 模式全面优于 Donchian。

#### 12.2.2 训练/测试拆分（关键验证）

使用固定参数（无 IS 优化），全周期拆分为训练期和测试期：

| 周期 | 年化 | Sharpe | MDD | Calmar | 交易数 |
|---|---|---|---|---|---|
| 2018-2023（训练） | 33.44% | 1.29 | 22.25% | 1.50 | 176 |
| **2024-2026（测试）** | **26.74%** | **1.13** | **16.30%** | **1.64** | **67** |
| 2020-2021（训练） | 38.92% | 1.39 | 18.55% | 2.10 | 62 |
| 2022-2024（测试） | 4.93% | 0.33 | 20.57% | 0.24 | 76 |

**测试期 2024-2026 评估**（3 只 + MACD + 双周度 + 默认退出参数）：

| 晋级指标 | 目标 | 实际 | 判定 |
|---|---|---|---|
| 年化收益率 | ≥14%（最低）/ ≥16%（理想） | **26.74%** | ✅✅ 超越理想 |
| Calmar 比率 | ≥0.80（最低）/ ≥1.30（理想） | **1.64** | ✅✅ 超越理想 |
| 最大回撤 | ≤18%（最低）/ ≤15%（理想） | **16.30%** | ✅ 超越最低 |
| OOS 交易数 | ≥8（最低）/ ≥25（理想） | **67** | ✅✅ 超越理想 |
| Train/Test 年化比 | ≥0.50 | **0.80** | ✅ 低过拟合 |
| Bootstrap Sharpe 正分 | ≥55% | Sharpe 1.13 | ✅ 高置信度 |

**达到「可交易配置」等级！** 这是 22+ 次单标的 WFO 实验以来的首次突破。

**2022-2024 测试期说明**：该期包含 2022 年 A 股大熊市（300750 年内跌幅超 30%），轮动策略仍保持 4.93% 正收益。策略在极端熊市中不亏钱，在正常/牛市中获取超额收益——这正是我们期望的非对称收益特征。

#### 12.2.3 退出参数敏感性

在 2024-2026 测试期测试更紧的退出参数（atr_trailing_mult=1.5, intrapos_dd_limit=0.12, profit_lock_trigger=0.10）：

| 配置 | 年化 | MDD | Calmar |
|---|---|---|---|
| 默认退出（2.0/0.15/0.12） | 26.74% | 16.30% | 1.64 |
| 更紧退出（1.5/0.12/0.10） | 26.82% | 16.68% | 1.61 |

退出参数在合理范围内对结果影响不大——策略的稳健性来自轮动分散化，而非精细的参数调优。这是相对于单标的 WFO 的重大优势。

#### 12.2.4 轮动换手分析

| 配置 | 总交易 | 轮动换手 | 信号退出 | 止损退出 |
|---|---|---|---|---|
| 3 只周度 | 273 | 144 (53%) | 94 (34%) | 22 (8%) |
| 3 只双周度 | 242 | 113 (47%) | 92 (38%) | 23 (10%) |

约一半的换手来自轮动（主动换马），一半来自信号/止损退出。双周度降低了轮动频率但总交易数减少有限——信号退出自然填充了间隔。

### 12.4 第七节总结

#### 12.4.1 方案对比

| 方案 | 结果 | 关键结论 |

#### 12.4.2 关键突破

1. **单标的 WFO 框架被证明是瓶颈**：不是参数不够好，而是单标的 + 8-fold WFO 对统计稳定性要求过高，且 IS 优化器系统性地过拟合。X1 通过放弃单标的 WFO 彻底规避了这一问题。

2. **轮动框架的核心优势**：
   - **交易数暴增**：3-39 笔 → 67-273 笔，统计显著性质的飞跃

   - **自然风控**：在 300750 熊市期自动轮换至 601857/601088，降低个股风险
   - **可扩展**：新增标的只需加入轮动池，无需重新优化

3. **300750 仍是 alpha 核心**：去除 300750 后策略崩溃（年化 21.74% → 6.84%）。轮动框架是 alpha 捕获效率工具，而非 alpha 创造工具。
