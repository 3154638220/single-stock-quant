## 阶段一：交易成本真实化（基础性修复）

### 1-1 接入 `TransactionCostParams`（非对称成本）

**问题**：`run_single_stock_backtest()` 当前用单一 `cost_bps=15.0` 对买卖两侧对称扣除，

这意味着当前回测少扣了卖出印花税，成本被低估约 5bps/笔。

**改动位置**：
- `src/backtest/single_stock.py`：`run_single_stock_backtest()` 签名增加 `cost_params` 参数，
  将买入时乘以 `cost_params.buy_fraction()`，卖出时乘以 `cost_params.sell_fraction()`，

- `src/settings.py` / `config.yaml.example`：新增 `backtest.transaction_cost` 子节点。

**核心改动**（伪代码）：

```python
# 买入
shares = cash * (1.0 - cost_params.buy_fraction()) / price

# 卖出
cash = shares * price * (1.0 - cost_params.sell_fraction())
```

**配置**：

```yaml
backtest:
  transaction_cost:
    commission_buy_bps:   2.5
    commission_sell_bps:  2.5
    slippage_bps_per_side: 2.0
    stamp_duty_sell_bps:  5.0   # 印花税单向，卖出时收
```

**回测中的体现**：

- `PerformancePanel` 新增 `cost_model` 字段记录本次所用成本参数；
- `--compare-costs` 新选项输出不同成本假设下的绩效对比表（类似 `--compare-stops`）。

## 阶段二：持仓管理精细化

### 2-1 ATR 动态止损

**问题**：当前固定百分比止损（如 8%）对高波动股过紧、对低波动股过松，
导致无谓止损或风险敞口不一致。ATR 止损根据近期波动率自适应调整阈值。

**改动位置**：`src/backtest/single_stock.py`，新增 `atr_stop_multiplier` 参数。

**规则**：

```
ATR_N = 近 N 日 True Range 的均值（默认 N=14）
止损价格 = 买入价 - atr_stop_multiplier × ATR_N（于买入当日计算一次，持仓期不变）

若当日收盘 < 止损价格 → 次日开盘强制平仓
exit_reason = "atr_stop"
```

**配置**：

```yaml
backtest:
  atr_stop_multiplier: 2.0   # 0 表示关闭；与 stop_loss_pct 二选一或同时启用取更严
  atr_stop_period:     14
```

**实现细节**：
1. 在 `_prepare_ohlcv()` 之后立即预计算全序列 ATR，挂到 `df["atr14"]`。
2. 买入当日记录 `atr_stop_price = entry_price - multiplier × df.loc[buy_idx, "atr14"]`。
3. 在持仓循环中和 `stop_loss_pct` 并行判断，取更早触发者。
4. `SingleStockBacktestResult` 新增 `atr_stop_exits: int`。

**与 WFO 集成**：`atr_stop_multiplier` 纳入 WFO 搜索空间（见阶段四）。

**预期回测效果**：高波动期间止损价格更宽，减少噪声止损次数（`atr_stop_exits` 下降）；
低波动期间止损更紧，单笔最大亏损缩小；整体 Calmar 比率提升。

### 2-2 基于风险的仓位定量（Fixed Fractional Sizing）

**问题**：现在每笔买入均满仓（100% 资金），导致每笔交易的实际风险暴露
随股票波动率大幅变化。波动大的股票单笔亏损可远超预期。

**改动位置**：`src/backtest/single_stock.py`，在买入执行时加入仓位计算逻辑。

**规则**：

```
每笔交易最大允许亏损 = total_equity × risk_per_trade_pct
止损距离（点数）= entry_price × stop_loss_pct    （或 atr_stop_multiplier × ATR）
仓位股数 = 最大允许亏损 / 止损距离 / entry_price  （再乘 entry_price 得资金量）
仓位上限 = position_size_cap × total_equity       （防止无止损时满仓）
```

**配置**：

```yaml
backtest:
  risk_per_trade_pct:  0.02   # 每笔风险不超过总资金 2%；0 表示关闭（仍满仓）
  position_size_cap:   1.0    # 单笔仓位上限占总资金比例
```

**实现细节**：
1. 仅在 `stop_loss_pct > 0` 或 `atr_stop_multiplier > 0` 时生效（止损距离可知）。
2. 若两者均为 0，退化为满仓（与当前行为一致）。
3. `SingleStockBacktestResult` 新增 `avg_position_fraction: float`（平均仓位占比）。

**预期回测效果**：
- 每笔亏损被硬约束在总资金 2% 以内；
- 高波动标的自动减仓，低波动标的维持接近满仓；
- 最大回撤显著改善，代价是部分牛市收益减少。

---

### 2-3 止损后智能再入场

**问题**：触发止损后，若 dk_color 仍为红色（趋势持续），
策略需等到下一个颜色翻转 → 再翻回红的完整信号才能重新入场，
可能错过趋势延续的大段收益。

**改动位置**：`src/backtest/single_stock.py`，在止损执行后增加再入场判断。

**规则**：

```
若 exit_reason in {"stop_loss", "atr_stop", "trailing_stop"}：
  设置 cooldown_bars = N（默认 3，避免立即反复止损）
  冷却结束后：若 dk_color == "red" 且 dk_run_len >= reentry_min_run：
    触发一次新的买入（无需等待颜色翻转信号）
```

**配置**：

```yaml
backtest:
  stop_reentry_enabled:   true
  stop_reentry_cooldown:  3      # 止损后冷却 N 个交易日
  stop_reentry_min_run:   2      # 再入场要求颜色已持续 N 日（防止震荡顶部）
```

**预期回测效果**：在单边趋势行情中（如 2020 年科技牛市），止损后能续接趋势，
年化收益提升；`stop_loss_exits` 后跟随的无效平仓减少。

## 阶段三：信号防抖（减少震荡市鞭打）

### 3-1 颜色持续确认过滤（Persistence Filter）

**问题**：`compute_dktrend()` 在颜色第一天翻转时即发出信号。
震荡行情中颜色可能一日红、一日绿地来回抖动，产生大量假信号。

**改动位置**：`src/indicators/dktrend.py` 新增可选参数 `min_run_len`；
`src/signals/generator.py` 的 `generate_signals()` 同步透传。

**规则**：

```
仅在 dk_run_len >= min_run_len 时才将"颜色转红"升级为 BUY 信号
（即颜色已连续为红 min_run_len 日，且这是第 min_run_len 日才发信号）
```

**配置**：

```yaml
trend_signal:
  min_run_len: 2    # 1 表示关闭（原始行为）；建议 2~3
```

**实现细节**：
1. 修改 `compute_dktrend()` 中的信号生成逻辑：

```python
# 原始逻辑
signal.loc[(color == "red") & (prev_color == "green")] = "buy"

# 新逻辑（min_run_len=2 时）
signal.loc[(color == "red") & (run_len >= min_run_len) & (run_len.shift(1) < min_run_len)] = "buy"
```

2. `DKTrendParams` 新增 `min_run_len: int = 1` 字段（默认 1 保持原行为）。
3. WFO 参数网格可搜索 `min_run_len: [1, 2, 3]`。

**与现有逻辑兼容性**：
- 默认值 1 完全等价于当前代码，无破坏性。
- `apply_volume_confirmation()` 在此之后仍正常运行（先持续确认，再量能确认）。

**预期回测效果**：
- 交易次数减少 20–40%（主要过滤震荡假信号）；
- 单笔平均持有期延长（进入更坚实的趋势）；
- 胜率和平均每笔收益上升；
- 在趋势市效果更好，但趋势起点略有延迟（代价）。

**问题**：所有 BUY 信号被同等对待，但部分信号伴随更强的支撑（高量能、高共振、

**改动位置**：`src/signals/types.py` 新增 `SignalQuality` 枚举；

**回测中的体现**：

## 阶段四：WFO 参数搜索扩展

### 4-1 止损与防抖参数联合寻优

**问题**：当前 WFO 只搜索 MACD 参数，但 `stop_loss_pct`、`atr_stop_multiplier`、
`min_run_len` 同样对 OOS 绩效有显著影响。将这些参数纳入联合搜索可找到更优的

**改动位置**：`src/backtest/wfo.py`，扩展 `_params_with()` 的覆盖逻辑，使其能
将 `stop_loss_pct`、`min_run_len` 等参数传递给 `run_single_stock_backtest()`。

**默认扩展参数网格**：

```yaml
wfo:
  param_grid:
    macd_fast:         [8, 10, 12, 14]
    macd_slow:         [22, 26, 30]
    macd_signal:       [7, 9, 11]
    stop_loss_pct:     [0.05, 0.08, 0.10]   # 新增
    min_run_len:       [1, 2, 3]             # 新增
```

**注意**：参数网格扩展后组合数从 36 增到 36×3×3=324，DSR 的 `n_trials=324`
会对 Sharpe 施加更强惩罚。这是**有意为之**——避免误以为更多参数等于更好的策略。

**关键实现**：

```python
def _params_with(base: DKTrendParams, overrides: dict, mode_value: str,
                 bt_overrides: dict | None = None) -> tuple[DKTrendParams, dict]:
    """返回 (trend_params, backtest_kwargs)"""
    ...
    bt_kwargs = {}
    for key in ["stop_loss_pct", "min_run_len", "atr_stop_multiplier"]:
        if key in overrides:
            bt_kwargs[key] = overrides.pop(key)
    return DKTrendParams.from_mapping(data), bt_kwargs
```

`run_single_stock_backtest()` 调用处拆包传入 `bt_kwargs`。

## 阶段五：统计有效性验证

### 5-1 蒙特卡洛置换检验（Permutation Test）

**问题**：策略的 Sharpe=0.85 是否真实有效？还是恰好在历史数据上碰对了？
Monte Carlo 置换检验通过打乱信号日期，生成策略 Sharpe 的"零假设分布"，
给出 p-value。

**新增文件**：`src/backtest/permutation_test.py`

**核心逻辑**：

```python
def run_permutation_test(
    ohlcv: pd.DataFrame,
    params: DKTrendParams,
    n_permutations: int = 1000,
    **bt_kwargs,
) -> PermutationTestResult:
    """
    1. 运行真实策略，得到 observed_sharpe。
    2. 循环 n_permutations 次：
       a. 将 ohlcv 的行随机打乱（保留同一天的 OHLCV 关联，打乱日期顺序）
       b. 运行相同策略，记录 null_sharpe[i]
    3. p_value = 比 observed_sharpe 更高的 null_sharpe 占比
    """
```

**输出**：`PermutationTestResult` 包含：
- `observed_sharpe`
- `null_sharpe_mean`, `null_sharpe_p95`
- `p_value`（单尾，越低越好）
- `is_significant`（p_value < 0.05）

**使用方式**：

```bash
python scripts/run_backtest_single.py --symbol 600930 \
    --mode macd_cross \
    --permutation-test \
    --n-permutations 500
```

**回测中的体现**：若 `p_value > 0.10`，在报告中打印警告：
`⚠️  策略 Sharpe 未通过置换检验（p=0.12），可能为噪声拟合`。

## 不纳入本次计划的项目

| 功能 | 排除原因 |
|---|---|
| LSTM / XGBoost 择时 | 当前数据量不足（单股 5 年约 1200 行），过拟合概率极高 |

| 做空 / T+0 | A 股散户限制多 |
| 实时推仓到券商 API | 合规与技术复杂度高，另起规划 |
| 情绪因子（新闻 NLP） | 需外部数据接口，超出当前工程范围 |
